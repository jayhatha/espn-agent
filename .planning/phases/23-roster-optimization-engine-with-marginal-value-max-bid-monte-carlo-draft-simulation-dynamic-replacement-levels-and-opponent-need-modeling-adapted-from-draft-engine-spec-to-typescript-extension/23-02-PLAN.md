<objective>
Build the bid optimizer (binary-search max bid), opponent need model, and Monte Carlo draft simulation as pure TypeScript functions with test coverage.

Purpose: These three modules consume the SGP and roster optimizer from Plan 01 to produce actionable draft recommendations. The bid optimizer answers "what's the most I should pay?", the opponent model estimates "what will others pay?", and Monte Carlo answers "should I bid at all?" These are the decision-layer modules that transform raw valuations into draft strategy.

Output: `bid-optimizer.ts`, `opponent-model.ts`, and `monte-carlo.ts` in `packages/extension/lib/engine/`, with companion test files. New signal types added to `types.ts`.

**Create `opponent-model.ts`:**

1. `buildOpponentModel(teamRosters, allTeamBudgets, rosterSlots, allPicks, inflationFactor): OpponentModel`
   - For each team in teamRosters: count picks by normalized position, compare to rosterSlots to find unfilled positions. Store in `teamNeeds` Map.
   - Copy allTeamBudgets into `teamBudgets` Map (normalize team name to team key).
   - Compute competitionFactors: for each position in rosterSlots, count how many teams still need that position, divide by total teams.
   - **CRITICAL: The RESEARCH.md Pattern 4 code example hardcodes `inflationFactor: 1.0` — this is a placeholder. Set `OpponentModel.leagueInflationFactor` to the passed-in `inflationFactor` parameter, NOT hardcoded 1.0.** This value comes from the existing `computeInflation()` in inflation.ts and is already computed in the engine pipeline.

2. `estimateMarketPrice(playerSGP, totalRemainingValue, totalRemainingBudget, competitionFactor): number`
   - Base price = `max(1, playerSGP * (totalRemainingBudget / totalRemainingValue))` if totalRemainingValue > 0, else $1.
   - Competition adjustment = `1 + (competitionFactor * 0.2)`.
   - Return `Math.round(basePrice * competitionAdjustment)`.

3. `computePositionCompetition(playerPositions, competitionFactors): number`
   - Return the max competition factor across the player's eligible positions.
   - Used by bid optimizer to get competition score for the nominated player.

**Create `bid-optimizer.ts`:**

1. `computeMaxBid(nominatedPlayer, availablePlayers, sgpVectors, budget, rosterSlots, opponentModel): BidOptimizerResult`
   - Extract nominated player's index in availablePlayers to get their SGP from sgpVectors.playerSGPs.
   - Baseline: call `optimizeRoster` with availablePlayers EXCLUDING nominated player, using their SGP values. This gives baseline team value.
   - Binary search: `lo = 1`, `hi = min(budget - totalRemainingSlots, maxReasonableBid)` where `maxReasonableBid` is the player's SGP-proportional value * 2 (capped at budget). Use `hi = min(budget - unfilled_slots + 1, max(1, Math.ceil(nominatedPlayer.dollars * 3)))` as a reasonable upper bound.
   - Loop while `lo < hi`: `mid = (lo + hi + 1) >> 1`. Call `optimizeRoster` with all available players, locking nominated player at cost `mid`. If `withPlayer.totalSGPValue >= baseline.totalSGPValue`, set `lo = mid`, else `hi = mid - 1`.
   - Compute `expectedMarketPrice` using `estimateMarketPrice` from opponent model.
   - Return `{ maxBid: lo, valueSurplus: lo - expectedMarketPrice, baselineValue, withPlayerValue, expectedMarketPrice }`.

**Create `monte-carlo.ts`:**

1. `runMonteCarlo(params): MonteCarloResult`

   Parameters:
   ```typescript
   interface MonteCarloParams {
     availablePlayers: PoolPlayer[];
     sgpValues: number[];
     myCurrentRoster: PoolPlayer[];
     myBudget: number;
     opponentBudgets: number[];
     rosterSlots: Record<string, number>;
     nominatedPlayer?: PoolPlayer;      // If present, simulate with vs without
     nominatedBid?: number;
     numSimulations?: number;           // Default 200
   }
   ```

   Return type (add to types.ts):
   ```typescript
   export interface MonteCarloResult {
     expectedTeamValue: number;
     valueStdDev: number;
     bidEV: number;           // EV if we win the nominated player
     passEV: number;          // EV if we pass
     shouldBid: boolean;      // bidEV > passEV
     simCount: number;
     computeTimeMs: number;
   }
   ```

   Implementation:
   - For each simulation:
     a. Create a Set of available player indices (do NOT splice arrays — use index sets per Research pitfall 5).
     b. If `nominatedPlayer` is provided, two scenarios per sim:
        - "bid" scenario: lock nominated player into my roster at `nominatedBid`, remove from available set.
        - "pass" scenario: opponent takes nominated player (remove from available set).
     c. Simulate remaining draft rounds: for each remaining roster spot (mine and opponents'), pick the highest-SGP affordable player from the available set. For opponents, add noise: multiply each player's SGP by a random factor `0.8 + Math.random() * 0.4` (uniform jitter) to simulate different valuations.
     d. After simulation, compute my team's total SGP with the greedy-filled remaining roster.
     e. Record the total team SGP for bid and pass scenarios.
   - Compute mean and stddev across all simulations for both scenarios.
   - `shouldBid = bidEV > passEV`.

2. `weightedShuffle(indices: number[], sgpValues: number[]): number[]` (internal helper)
   - Return indices sorted by `sgpValues[i] * (0.8 + Math.random() * 0.4)` descending.
   - This creates different orderings per simulation while keeping high-value players near the top.
