<objective>
Build the foundational SGP (Standings Gain Points) valuation model and greedy roster optimizer as pure TypeScript functions with full test coverage.

Purpose: These two modules are the computational foundation for Phase 23. The SGP model converts raw FanGraphs projections into a single normalized value per player (accounting for replacement levels and positional scarcity). The roster optimizer uses these values to solve the "best roster given budget" problem via greedy knapsack. Both modules are prerequisites for the bid optimizer, Monte Carlo simulation, and opponent modeling in Plan 02.

Output: `sgp.ts` and `roster-optimizer.ts` in `packages/extension/lib/engine/`, with companion test files. New types added to `types.ts`.
</objective>

**Create `sgp.ts` with three exported functions:**

1. `buildSGPVectors(players: PoolPlayer[], categories: Category[], rosterSlots: Record<string, number>, totalTeams: number): SGPVectors`
   - Build stat vectors: for each category, extract the stat value from each player into an array (O(n*cats)).
   - Compute per-category stats: mean, std (population stddev), replacementValue.
   - Replacement value: for each category, find players eligible at the position most associated with that category (hitters for HR/RBI/SB/R/AVG, pitchers for W/K/SV/ERA/WHIP). Sort eligible players by that stat descending (or ascending for LOWER_BETTER). The replacement level is the value of the player at index `slotsPerPosition * totalTeams`. If that index exceeds the array, use the last player's value.
   - For position-specific replacement: use a mapping of stat_key to primary position (HR->general hitter, SV->RP, etc.) but for simplicity, compute replacement as the Nth best value across ALL eligible players for that stat. The "N" is total roster slots (sum of all position slots * totalTeams).
   - Compute playerSGPs: for each player, sum `(stat - replacementValue) / std` across categories. For LOWER_BETTER categories, negate: `-(stat - replacementValue) / std` (so lower ERA = positive SGP). Guard against std=0 (return 0 for that category).
   - Return `{ statVectors, categoryStats, playerSGPs, computedAt: Date.now() }`.

2. `applyScarcityAdjustment(baseSGP: number, position: string, remainingSlots: number, remainingPlayers: number): number`
   - Compute `scarcityFactor = remainingSlots / remainingPlayers` (guard against 0 denominator, return baseSGP).
   - Apply multiplier from `SCARCITY_MULTIPLIERS`: `{ C: 1.5, SS: 1.3, "2B": 1.2 }`. Default multiplier = 1.0.
   - Return `baseSGP * (1 + (scarcityFactor - 1) * multiplier)`.

3. `getPlayerStat(player: PoolPlayer, category: Category): number` (internal helper, but export for testing)
   - For counting stats: return `player.stats[category.stat_key] || 0`.
   - For rate stats: return `player.stats[category.stat_key] || 0` (use the precomputed rate from FanGraphs data directly, per Research pitfall 3).

**Create `roster-optimizer.ts` with:**

1. `SLOT_PRIORITY` constant: defines slot assignment order from most-restrictive to least-restrictive:
   ```typescript
   const SLOT_PRIORITY = ["C", "SS", "2B", "3B", "1B", "OF", "CI", "MI", "UTIL", "P", "BN"];
   ```

2. `FLEX_ELIGIBILITY` mapping: which positions can fill flex slots:
   ```typescript
   const FLEX_ELIGIBILITY: Record<string, string[]> = {
     CI: ["1B", "3B"],
     MI: ["2B", "SS"],
     UTIL: ["C", "1B", "2B", "3B", "SS", "OF", "DH"],
     BN: ["C", "1B", "2B", "3B", "SS", "OF", "DH", "SP", "RP", "P"],
     P: ["SP", "RP"],
   };
   ```

3. `findBestSlot(playerPositions: string[], remainingSlots: Map<string, number>): string | null`
   - Normalize each player position via the normalizePosition function (import from scarcity.ts or inline the same logic).
   - Iterate through SLOT_PRIORITY. For each slot with remaining count > 0:
     - If the slot is a dedicated position (C, 1B, 2B, etc.) and the player has that position, return slot.
     - If the slot is a flex slot (CI, MI, UTIL, BN, P) and the player has any of the eligible positions for that flex, return slot.
   - Return null if no slot available.

4. `optimizeRoster(players: PoolPlayer[], sgpValues: number[], budget: number, rosterSlots: Record<string, number>, lockedPlayers?: { player: PoolPlayer; cost: number }[]): RosterOptimizationResult`
   - `RosterOptimizationResult` interface: `{ roster: PoolPlayer[], totalSGPValue: number, budgetUsed: number, unfilledSlots: number }`.
   - Initialize `remainingSlots` as a Map from `rosterSlots`.
   - If `lockedPlayers` provided: for each, decrement the appropriate slot and subtract cost from budget. Reserve $1 per remaining unfilled slot.
   - Sort players by `sgpValues[i] / Math.max(1, player.dollars)` descending (SGP/$ efficiency).
   - Greedily iterate: for each player, if affordable (cost <= budget - reservedMinimum) and a slot exists (via `findBestSlot`), add to roster.
   - Return result with totalSGPValue = sum of SGP values for all rostered players (including locked).
