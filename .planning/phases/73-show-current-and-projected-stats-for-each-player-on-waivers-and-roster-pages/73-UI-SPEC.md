### New Component: `PlayerStatLine`

**File:** `src/components/league/PlayerStatLine.tsx`

**Purpose:** Renders a single compact stat line below the player name in any player list. Position-aware — shows hitter or pitcher stats based on `positions` array. Handles null gracefully with "--".

**Props:**

```typescript
interface PlayerStatLineProps {
  components: Record<string, number> | null;
  label: "YTD" | "Proj RoS";
  positions: string[];
}
```

**Visual specification:**

- Outer element: `<div className="text-data font-mono text-shell-muted mt-1">`
- Label prefix: `<span className="text-caption text-content-tertiary dark:text-content-tertiary mr-1 font-sans not-italic">{label}</span>` — label uses Inter (not mono), forcing `font-sans` since the parent is mono
- Stat values: inline, space-separated, format: `KEY: VALUE`
- Missing stat (null or IP=0 for rate stats): render `--`
- No wrapping — single line, truncates on overflow

**Hitter stat order (left to right):** HR · R · RBI · SB · AVG · OBP

**Pitcher stat order (left to right):** W · SV · K · ERA · WHIP

**Decimal places:**
- HR, R, RBI, SB, W, SV, K: 0 decimal places
- AVG: 3 decimal places (e.g., .278)
- OBP: 3 decimal places (e.g., .352)
- ERA: 2 decimal places (e.g., 3.41)
- WHIP: 3 decimal places (e.g., 1.152)

**Null guard:** If `components` is null, render nothing (return null). If computed rate stat has IP=0 or AB=0, display "--" for that stat only.

**Label color:** "Proj RoS" label uses `text-shell-accent` (indigo) to visually distinguish projections from historical. "YTD" label uses `text-content-tertiary` (neutral gray).

## Page-Level Interaction Contracts

### Waivers Page — Manual Eval Mode (`/leagues/[id]/waivers` with viewMode="manual")

**Free agent list (left column):**

Each player card renders:
1. Line 1: Player name (`text-body-sm font-medium text-shell-text`) + position/team (`text-data text-shell-muted`)
2. Line 2 (new): `PlayerStatLine` with `label="Proj RoS"` and RoS projection components
3. Line 3 (new, conditional): `PlayerStatLine` with `label="YTD"` and current season stats — only rendered if `currentStats` is non-null

**Vertical stack within player card:**
```
[Player Name]                          [pct owned]
[Position • Team]
[Proj RoS  HR: 22 R: 88 RBI: 91 SB: 12 AVG: .278 OBP: .352]
[YTD       HR: 8  R: 34 RBI: 38 SB: 4  AVG: .261 OBP: .334]  ← only if currentStats non-null
```

**Roster drop list (right column):**

Same layout — each roster player shows:
1. Line 1: Player name + roster slot badge
2. Line 2 (new): `PlayerStatLine` with `label="Proj RoS"`
3. Line 3 (new, conditional): `PlayerStatLine` with `label="YTD"` — only if currentStats non-null

**No expand/collapse interaction on the waivers page.** Both stat lines display inline below the player name at all times. The waivers page is a selection picker — scannability is the priority over information density control. This matches the RESEARCH.md recommendation for "inline one-line stat summary."

### Roster Page (`/leagues/[id]/lineup` — currently "Lineup Optimizer")

The nav item "Roster" maps to `/lineup`. This page currently shows lineup swap recommendations, not a raw roster list. Phase 73 scope per RESEARCH.md open question #1 resolution: add a "View Roster Stats" section at the bottom of the lineup page showing all rostered players with both stat lines.

**Roster stats section layout:**

- Section heading: "Your Roster" (`text-h4 font-medium text-shell-text mb-3`)
- Rendered as a `StatsTable` with sortable columns (uses existing StatsTable component)
- Table column order: Player | Pos | Team | [position-specific stat columns]
- Hitter columns: HR | R | RBI | SB | AVG | OBP | [Proj RoS prefix on column header]
- Pitcher columns: W | SV | K | ERA | WHIP | [Proj RoS prefix on column header]
- The table cannot mix hitters and pitchers in a single column set — render two tables: "Hitters" and "Pitchers"
- Each table is independently sortable
- YTD stats shown as a sub-row or second row per player using the same `PlayerStatLine` component at `text-caption` size directly beneath the proj row

**Note:** If the scope is determined to be waivers-only (no roster page changes), the Roster Stats section is dropped and only the waivers page gets stat lines. The waivers page changes are unambiguously in scope; the roster/lineup page changes are additive based on the phase title "waivers and roster pages."

## Empty and Error States

### Empty State — No Projections for Player

**Context:** Free agent or roster player where `projections` is null (player not in latest projection CSV run).

**Display:** Omit the "Proj RoS" stat line entirely. Do not show a placeholder row. The absence of the line is the signal.

**Copy:** No explicit empty state copy at the player level — the line is simply absent.

### Empty State — No Current Stats for Player

**Context:** `currentStats` is null (player not synced by PlayerPoolSyncAgent — expected for most free agents).

**Display:** Omit the "YTD" stat line entirely. Most free agents will not have this line. This is expected behavior, not an error.

**Copy:** No explicit copy — line absence is the signal. Expected for ~80% of free agents.

### Empty State — No Free Agents Loaded

**Context:** Free agent list returns empty array.

**Heading:** "No free agents found"
**Body:** "Run a snapshot to sync available free agents from ESPN."
**CTA:** None — user must trigger snapshot from Dashboard.

### Empty State — No Roster Loaded

**Context:** Roster API returns empty array or team not selected.

**Heading:** "No roster data"
**Body:** "Select your team, then run a snapshot to load your roster."
**CTA:** Link to league dashboard page.

### Error State — API Failure on Free Agents

**Copy:** "Could not load free agents. Check that your league snapshot is up to date and try again."
**Rendered with:** `ErrorAlert` component (existing) with `onRetry` prop pointing to query refetch.

### Error State — API Failure on Roster

**Copy:** "Could not load roster. Check that your league snapshot is up to date and try again."
**Rendered with:** `ErrorAlert` component with `onRetry`.

## Interaction States

### Player Row Selection (waivers manual eval)

Unchanged from existing behavior. Selecting a free agent highlights the row with `bg-positive-light border-l-4 border-positive` (add variant). Selecting a roster player highlights with `bg-negative-light border-l-4 border-negative` (drop variant). The stat lines inherit the row background — no separate highlight logic for stat lines.

### Loading State (stat lines)

During the initial query load, the existing `LoadingSkeleton` component handles the full card area. No per-stat-line skeleton is needed — the skeleton already covers the player list area.

### Sort Interaction (roster table)

StatsTable handles sorting natively. Default sort: HR descending for hitter table, K descending for pitcher table. All stat columns are sortable. Player name column is sortable (alphabetical).

## Accessibility

- All numeric stat values render in `font-mono` — no separate aria-label needed for numbers.
- The "YTD" and "Proj RoS" labels are visible text — screen readers will read them inline.
- Stat lines use `<div>` not `<span>` — they are block-level below the name line, not inline with it.
- No interactive elements within the stat line itself — clicking a player row selects the player, not the stat line.
- Color is not the sole indicator of stat quality (there are no green/red values on stats in this phase — stats are informational, not evaluated).
