    Create agent following existing agent patterns (see snapshot-orchestrator.ts, projections-ingest.ts):

    ```typescript
    import type { Logger } from "pino";
    import type { Kysely } from "kysely";
    import type { Database } from "../db/schema.js";
    import { ESPNAdapter } from "../adapters/espn.js";

    export class PlayerPoolSyncAgent {
      constructor(
        private db: Kysely<Database>,
        private espnAdapter: ESPNAdapter,
        private logger?: Logger,
      ) {}

      async syncPlayerPool(season: number): Promise<SyncResult> {
        // 1. Fetch top 500 players by ownership from ESPN free agent endpoint
        //    Use generic league call (no auth needed for free agent data)
        //    Filter to players with pct_owned > 1% to avoid deep benches

        // 2. For each player, extract:
        //    - espn_player_id (for matching to existing player records)
        //    - name, team, positions
        //    - pct_owned (rostered percentage)
        //    - current season counting stats from stats array

        // 3. Upsert to player table:
        //    - ON CONFLICT (espn_player_id) DO UPDATE
        //    - Update pct_owned, current_season_stats_json, last_synced_at
        //    - Insert new players if espn_player_id not found

        // 4. Handle errors gracefully:
        //    - Wrap ESPN fetch in try/catch
        //    - If ESPN API fails, log error and return { success: false, error }
        //    - If partial data, mark stale players (last_synced_at > 7 days old)

        // 5. Return SyncResult:
        //    { success: boolean, playersUpdated: number, playersInserted: number, error?: string }
      }
    }

    export interface SyncResult {
      success: boolean;
      playersUpdated: number;
      playersInserted: number;
      error?: string;
    }
    ```

    **Key implementation details:**
    - Use ESPNAdapter.fetchFreeAgents() pattern (exists in espn.ts but may need generic version)
    - Extract counting stats from ESPN response (see snapshot-orchestrator for parsing pattern)
    - Store stats as JSONB: `{ AB, H, R, HR, RBI, SB, BB, IP, K, W, SV, HLD, QS }`
    - Use Kysely's `.onConflict()` for upsert pattern
    - Set last_synced_at to NOW() on successful update
    - No retry logic in agent (worker handles retries)

    **Error handling per user constraint (Claude's discretion):**
    - Choose: Keep stale data (return success=false but don't delete)
    - Log detailed error with ESPN response status
    - Mark operation as failed but preserve existing player data

    **2. Create player-pool-worker.ts:**

    Follow research pattern from 11-RESEARCH.md (node-cron section):

    ```typescript
    import cron from 'node-cron';
    import pino from 'pino';
    import { getDb } from '../db/connection.js';
    import { PlayerPoolSyncAgent } from '../agents/player-pool-sync.js';
    import { ESPNAdapter } from '../adapters/espn.js';

    const logger = pino({
      level: process.env.LOG_LEVEL || 'info',
      name: 'player-pool-worker',
    });

    const CURRENT_SEASON = 2025; // Update annually or read from env var

    // Schedule daily at 4:00 AM Eastern Time
    cron.schedule('0 4 * * *', async () => {
      logger.info('Starting daily player pool sync');
      const startTime = Date.now();

      try {
        const db = getDb();
        const espnAdapter = new ESPNAdapter(logger);
        const syncAgent = new PlayerPoolSyncAgent(db, espnAdapter, logger);

        const result = await syncAgent.syncPlayerPool(CURRENT_SEASON);

        if (result.success) {
          const duration = Date.now() - startTime;
          logger.info({
            playersUpdated: result.playersUpdated,
            playersInserted: result.playersInserted,
            durationMs: duration,
          }, 'Player pool sync completed successfully');
        } else {
          logger.error({ error: result.error }, 'Player pool sync failed');
        }
      } catch (error) {
        logger.error({ error }, 'Player pool sync crashed');
      }
    }, {
      timezone: 'America/New_York', // ESPN updates typically overnight Eastern
    });

    logger.info('Player pool sync cron job scheduled (4:00 AM ET daily)');

    // Keep process alive
    process.on('SIGTERM', () => {
      logger.info('SIGTERM received, shutting down gracefully');
      process.exit(0);
    });
    ```

    **Why 4 AM ET:**
    - ESPN typically updates stats overnight after West Coast games end (11 PM PT = 2 AM ET)
    - 4 AM gives 2-hour buffer for ESPN processing
    - Runs before typical draft start times (evenings)

    **No BullMQ:**
    - Research recommends node-cron for simple daily jobs (BullMQ repeatable APIs deprecated)
    - Single job, no queue coordination needed
    - Simpler deployment (no Redis dependency for this worker)

    **Deployment note:**
    - This worker must run as separate process alongside main API server
    - Add to docker-compose or Railway Procfile: `player_pool_worker: pnpm --filter @espn-fantasy/backend worker:player-pool`
