# Phase 07.1 Plan 02: Dynamic Category Dropdown Summary

**One-liner:** Category dropdown now fetches from league settings API, showing only configured categories (no HLD if league doesn't use it).

## Objective Complete

Replaced hardcoded category list on the trends page with dynamic categories fetched from the `/api/leagues/:leagueId/categories` endpoint. The dropdown now reflects each league's actual scoring configuration.

## What Was Built

### Frontend Changes

**packages/frontend/src/lib/api.ts**
- Added `getLeagueCategories(leagueId: number)` method to API client
- Fetches from `/api/leagues/:leagueId/categories` endpoint

**packages/frontend/src/app/leagues/[id]/trends/page.tsx**
- Removed hardcoded categories array (AVG, HR, R, RBI, SB, WHIP, ERA, K, W, SV, HLD)
- Added `useQuery` to fetch league categories dynamically
- Derived categories array from API response: `{ value: stat_key || category_id, label: name }`
- Added `useEffect` to update selectedCategory when categories load (defaults to first available)
- Updated loading state to include `categoriesLoading` when in category view mode
- Disabled category dropdown while categories are loading

## Technical Notes

**Category Value Mapping:**
The API returns categories with `stat_key` (preferred) and `category_id` (fallback). Using `stat_key` ensures consistency with backend category identification.

**Loading State Pattern:**
Only includes `categoriesLoading` in overall loading check when `viewMode === "category"` to avoid unnecessary loading spinners in other views.

**Default Selection:**
The `useEffect` checks if current `selectedCategory` is valid whenever categories load. If not found in the new list, it auto-selects `categories[0].value`. This handles initial load and potential category list changes.

**Backend Endpoint:**
The `/api/leagues/:leagueId/categories` endpoint (already implemented in timeseries.ts) fetches from `league_settings_version.settings_json.categories`, ensuring accuracy per league.
