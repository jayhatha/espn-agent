  <action>
Create `bid-ceiling.test.ts` testing bid/pass decision logic through `computeMaxBid` from `../engine/bid-optimizer`.

Use a realistic 15-player pool with varied dollar values ($1-$45) and positions (mix of OF, 1B, SS, C, SP). Use simple `rosterSlots: { OF: 3, "1B": 1, SS: 1, C: 1, SP: 3, UTIL: 1 }`. Pre-compute SGP values as a parallel array (proportional to dollar value for simplicity: sgp[i] = player.dollars * 0.2).

Create a helper `makeOpponentModel()` returning a minimal OpponentModel with empty teamNeeds, teamBudgets, and uniform 0.5 competition factors.

**BID tests (price < model value):**
1. "BID when player value exceeds market price": Nominate a $30 player with budget=$200. maxBid should be > 1 (profitable to bid).
2. "maxBid increases with inflation": Same player, same budget, but pass `inflationFactor=1.3`. maxBid at 1.3 inflation should be >= maxBid at 1.0 inflation (inflation raises the upper bound of binary search).
3. "maxBid respects budget minus reserves": Budget=$15, rosterSlots has 10 unfilled. maxBid should be <= budget - (unfilled-1) = $6.

**PASS tests (price > model value):**
4. "maxBid=1 for replacement-level player": Nominate a $1 player with SGP near 0. maxBid should be 1.
5. "maxBid=1 when player not in pool": Nominate a player NOT in availablePlayers array. Result maxBid should be 1.

**Value surplus tests:**
6. "valueSurplus positive when maxBid > expectedMarketPrice": For a high-SGP player with low competition. Verify `result.valueSurplus > 0`.
7. "valueSurplus negative for replacement-level player": maxBid=1 but market may be higher. Verify `result.valueSurplus <= 0`.

**ASV market price override:**
8. "asvMarketPrice used as expectedMarketPrice when provided": Pass `asvMarketPrice=25`. Verify `result.expectedMarketPrice === 25`.
9. "asvMarketPrice rounds to integer, minimum 1": Pass `asvMarketPrice=0.3`. Verify `result.expectedMarketPrice === 1`.

**Baseline computation:**
10. "baselineValue computed from roster without nominated player": Verify `result.baselineValue > 0` for a non-trivial pool.
11. "withPlayerValue >= baselineValue at maxBid": By definition of binary search, adding the player at maxBid should be at least as good as baseline.

1. "never exceeds budget": Create pool where sum of all player dollars exceeds budget. Verify `result.budgetUsed <= budget`.
2. "reserves $1 per unfilled slot": Budget=$20, 10 slots. Most expensive player costs $15. Verify it's NOT selected if it would leave < $1 per remaining slot (reserve = slotsToFill - 1).
3. "fills cheapest $1 players when budget is tight": Budget=$10, 10 slots. Verify all slots filled with $1 players.

**Slot filling tests:**
4. "fills all positions when pool has enough players": 22-slot roster, pool of 30+ players covering all positions. Verify `result.unfilledSlots === 0`.
5. "respects position eligibility": A player with positions=["C"] should only fill C or UTIL/BN, not SS or OF.
6. "most-restrictive slot fills first": A C-eligible player should fill C slot before UTIL when both are open. Verify via slotAssignments.

**SP tier cap tests:**
7. "SP1 slot allows up to $18 pitcher": Pool has a $18 SP. With 0 SPs drafted, pitcher should be selected for SP/P slot.
8. "SP3+ slot rejects expensive pitchers": Pool has only $15 SPs. With 2 SPs already in roster (via lockedPlayers), the $15 SP exceeds tier 3 cap ($10). Verify it's skipped in favor of cheaper SP.
9. "tier cap clamps to SP5 ($3) for 4+ drafted SPs": Lock 4 SPs via lockedPlayers. Verify remaining SP slots only accept $3 or less pitchers.

**Locked players tests:**
10. "locked players consume their slot and budget": Lock a $30 OF player. Verify OF slot count decremented and budget reduced by $30.
11. "locked player SGP not double-counted": Lock a player, verify totalSGPValue doesn't include locked player's SGP (it's excluded from the greedy fill SGP sum; caller adds it separately).

**Backfill pass tests:**
12. "backfill fills slots when greedy pass leaves gaps": Create scenario where budget reserve prevents greedy fill but backfill force-places cheapest eligible player. Verify `result.unfilledSlots === 0`.
13. "backfill prefers tier-cap-compliant SPs": With SP slots needing backfill and 2 SPs already drafted, backfill should pick a SP within tier 3 cap over a more expensive one.
