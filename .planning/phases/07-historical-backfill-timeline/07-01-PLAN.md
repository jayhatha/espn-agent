**HistoricalBackfillAgent** — create `packages/backend/src/agents/historical-backfill.ts`:

Create a new agent class following the existing agent pattern (accepts `Kysely<Database>` db and optional `Logger`).

Constructor:
- Store db and logger
- Instantiate ESPNAdapter (same as SnapshotOrchestratorAgent does)
- Instantiate SnapshotOrchestratorAgent for reusing existing snapshot write logic

`backfillSeason` method signature:
```typescript
async backfillSeason(options: {
  leagueId: number;
  season: number;
  startWeek: number;
  endWeek: number;
  espnAuth?: ESPNAuthCookies;
  onProgress?: (progress: BackfillProgress) => Promise<void>;
}): Promise<BackfillResult>
```

`BackfillProgress` interface:
```typescript
interface BackfillProgress {
  stage: "pending" | "fetching" | "processing" | "completed" | "failed";
  completedWeeks: number;
  totalWeeks: number;
  currentWeek: number;
  percentage: number;
  errors?: string[];
}
```

`BackfillResult` interface:
```typescript
interface BackfillResult {
  success: boolean;
  weeksProcessed: number;
  weeksSkipped: number;
  weeksFailed: number;
  errors: string[];
}
```

Implementation of `backfillSeason`:
1. Calculate `totalWeeks = endWeek - startWeek + 1`
2. Call `onProgress` with stage="fetching", completedWeeks=0
3. Look up the league from DB to get `espn_league_id` and `season`
4. Loop from `startWeek` to `endWeek`:
   a. Call `this.espnAdapter.fetchHistoricalWeek(...)` (throttle is inside adapter)
   b. Compute `snapshotDate` for this week using the league's season. Use a simple heuristic: MLB Opening Day is approximately April 1 of the season year, so `snapshotDate = new Date(season, 3, 1 + (scoringPeriodId - 1) * 7).toISOString().split('T')[0]`. This is a rough approximation — the important thing is that each week gets a unique date in the right season.
   c. Archive raw payload to `league_raw_payload` with `scoring_period_id` set to the week number
   d. Normalize data via `this.espnAdapter.normalizeLeagueData()`
   e. Reuse `SnapshotOrchestratorAgent.executeSnapshot()` with `{ leagueId, snapshotDate, espnAuth, forceFresh: true }` to write snapshot data. The orchestrator already handles idempotent writes (ON CONFLICT patterns for all snapshot tables).
   f. **Transaction deduplication**: If the normalized data includes transactions, compute SHA-256 hash of each transaction's canonical fields (transactionId, type, timestamp, sorted items by playerId with fromTeamId/toTeamId/action, bidAmount). Use `crypto.createHash('sha256').update(JSON.stringify(canonical)).digest('hex').substring(0, 16)`. Insert into `league_transaction_event` with `ON CONFLICT DO NOTHING` on the unique constraint `(league_id, event_time, team_id, payload_hash)`.
   g. If a week fails, log the error, add to errors array, increment `weeksFailed`, and continue to next week (don't abort the whole backfill)
   h. After each week, call `onProgress` with updated completedWeeks and percentage
   i. 2-second throttle is already handled by the adapter — no additional delay needed between loop iterations
5. Call `onProgress` with stage="completed" (or "failed" if all weeks failed)
6. Return `BackfillResult` with counts

Export: `HistoricalBackfillAgent`, `BackfillProgress`, `BackfillResult`
