**Note:** `sgpValues[i]` must correspond to `allPlayers[i]` — these are parallel arrays aligned by index from the caller.

```typescript
export function computeShoppingList(params: {
  allPlayers: PoolPlayer[];
  sgpValues: number[];                       // Parallel to allPlayers — sgpValues[i] is SGP for allPlayers[i]
  needByPosition: Record<string, number>;   // Position -> unfilled slot count (CI/MI already expanded)
  remainingSlots: Record<string, number>;    // Raw remaining slots (for UTIL/P check)
  scarcitySignals: EnhancedScarcitySignal[];
  opponentModel: OpponentModel;
  myBudget: number;
  weakCategories: Set<string>;
  topN?: number;  // Default 3
}): ShoppingListSignal
```

**Algorithm:**

a. **Build position-to-players mapping (TARG-01, TARG-05):**
   - For each player in `allPlayers`, look at `player.positions` (e.g., `["1B", "3B"]`).
   - Normalize each position to uppercase.
   - For each position that exists in `needByPosition` (unfilled > 0), add the player to that position's candidate list.
   - Also check pitcher positions: if `needByPosition` has no "SP"/"RP" keys but `remainingSlots` has "P" > 0, map SP/RP players to a "P" group.
   - **Multi-position eligibility (TARG-05):** A player with positions ["1B", "3B"] appears in both the "1B" group and the "3B" group.

b. **Score and sort players within each position (TARG-01):**
   - For each player, compute `adjustedSgp` using the same formula as the existing top targets:
     - Base SGP from `sgpValues[playerIndex]`
     - Positional need boost: `sgp * (1 + maxNeed * 0.5)` where maxNeed = `needByPosition[position]` for the specific position group
     - Weak category boost: `1 + 0.3 * (number of weak categories the player's stats contribute to)`, capped at 2.0
   - Sort by `adjustedSgp` descending, take top N (default 3).

c. **Compute per-target pricing (TARG-02):**
   - For each target, compute `expectedMarketPrice` using `estimateMarketPrice()` from opponent-model.ts (same as existing topTargets).
   - Compute `maxBid` using the quick heuristic: `Math.min(myBudget, expectedPrice, Math.max(1, Math.ceil(player.dollars * 2.0)))` — do NOT use the expensive binary-search `computeMaxBid()` for shopping list targets. The binary search is only used for the currently nominated player.
   - `valueSurplus = maxBid - expectedMarketPrice`.

d. **Compute position priority score (TARG-03, PRIO-01):**
   - For each position group, compute `computePositionPriority()`:
     - `scarcityWeight` (40%): scarcity index from `scarcitySignals` for this position (0 if not found)
     - `slotWeight` (35%): `min(1.0, unfilledSlots / 3)` — 1 slot = 0.33, 2 slots = 0.67, 3+ slots = 1.0
     - `budgetFitWeight` (25%): fraction of top-N targets with `dollarValue <= myBudget * 0.4` (affordable relative to budget)
     - `priorityScore = scarcityWeight * 0.4 + slotWeight * 0.35 + budgetFitWeight * 0.25`

e. **Exclude filled positions (PRIO-02):**
   - Only create groups for positions where `needByPosition[pos] > 0`. This is already handled by step (a) — we only iterate positions in `needByPosition`.

f. **Sort groups by priority descending, return ShoppingListSignal.**

**Important:** Export a `computePositionPriority` helper for testability:
```typescript
export function computePositionPriority(
  scarcityIndex: number,
  unfilledSlots: number,
  affordableCount: number,
  totalTargets: number,
): number
```

**Performance note:** This function does NOT call `computeMaxBid()` (binary search). It reuses the quick SGP-share heuristic for max bid estimation. The function should complete in < 5ms for typical inputs.
