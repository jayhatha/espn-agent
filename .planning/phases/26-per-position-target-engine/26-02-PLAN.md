**5. Dynamic updates (TARG-04, PRIO-03):**

No additional work needed. The shopping list naturally recomputes because:
- `computeRosterOptimization()` is called every time `computeDraftEngine()` runs
- `computeDraftEngine()` runs when `allPicks` changes (via `useDraftEngineSignals` useMemo deps)
- The `needByPosition` and `remainingSlots` are recomputed from `input.myRoster` each time
- Scarcity signals are recomputed from `allPicks` each time
- When a position fills (all slots taken), `needByPosition` won't have that position, so `computeShoppingList` won't produce a group for it

The SGP cache (`sgpCacheKey`) already invalidates on `allPicks.length` change, so SGP values are fresh when the shopping list runs.
