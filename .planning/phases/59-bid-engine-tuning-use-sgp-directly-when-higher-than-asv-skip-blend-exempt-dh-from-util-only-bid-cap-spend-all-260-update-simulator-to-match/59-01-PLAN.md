**bid-optimizer.ts — SGP skip blend:**

In `computeMaxBid`, at the blend step (lines 98-105), change the logic:
- Current: `rawBlendedValue = sgpDollars * 0.4 + asvMarketPrice * 0.6`
- New: If `sgpDollars > asvMarketPrice` (and asvMarketPrice is valid/positive), set `rawBlendedValue = sgpDollars` directly (skip blend). Otherwise keep the existing blend formula.
- This ensures SGP is never diluted downward by a lower ASV. When our model says a player is worth more than the market, trust the model.
- Update the comment to explain the skip-blend logic.

**strategy-caps.ts — DH UTIL exemption:**

In `computeStrategyBidCap`, in the hitter need multiplier block (lines 133-149):
- Before applying the 0.7x UTIL multiplier, check if the player has "DH" in their `positions` array.
- If the player is DH-eligible AND the destination is "UTIL", skip the 0.7x reduction. DH players' natural slot IS UTIL — they are not "fallback" UTIL players.
- Add to capSource: `" -> need x1.0 (DH natural UTIL)"` when exemption applies.
- BN dampening (0.5x) still applies to DH players normally — being bench-bound is genuinely bad.

**strategy-caps.ts — Budget flush boost:**

Add a budget flush mechanism at the END of `computeStrategyBidCap` (after inflation adjustment, as the final step):
- Calculate: `slotsRemaining = sum of all values in input.remainingSlots` (if remainingSlots provided).
- Calculate: `budgetRemaining = BUDGET - input.hitterSpent - input.pitcherSpent` where BUDGET = 260 (import or use constant).
- Calculate: `minReserves = max(0, slotsRemaining - 1)` (must reserve $1 per remaining slot after this pick).
- Calculate: `excessBudget = budgetRemaining - minReserves - bidCap`.
- If `excessBudget > 0 AND slotsRemaining <= 5`: boost the bid by `Math.min(excessBudget, Math.ceil(excessBudget * 0.5))`. This spends roughly half the excess on each remaining pick, draining the budget progressively.
- If `slotsRemaining <= 2`: boost by the full `excessBudget` — last picks, spend it all.
- Add to capSource the boost amount.
- Add `TOTAL_BUDGET = 260` constant to `draft-constants.ts` or use inline. Prefer adding to draft-constants.ts for consistency.

Add `StrategyCapInput` field: no new fields needed — `remainingSlots`, `hitterSpent`, `pitcherSpent` already exist. Just need to compute `budgetRemaining` from them plus the known $260 total.

**strategy-caps.ts — Hitter bench overflow guard (bugfix):**

Currently `determineSlotDestination` returns "BN" as a catch-all when no dedicated/flex/UTIL slots remain. But there's no guard against drafting hitters when bench hitter slots are also full. The 0.5x BN multiplier reduces the bid but doesn't prevent it.

Add a new return value to `determineSlotDestination`: `"NONE"` — returned when ALL hitter slots (dedicated, flex, UTIL, BN) are filled. This requires knowing the bench hitter count, which isn't currently tracked in remainingSlots.

Simpler approach: In `computeStrategyBidCap`, after the need multiplier block, add a guard:
- If `destination === "BN"` for a hitter AND `(remainingSlots["BN"] ?? 0) <= 0`, return `{ bidCap: 0, capSource: "NO SLOT" }`.
- Check if BN is tracked in remainingSlots. If not, add a `benchHittersRemaining` field to `StrategyCapInput` (optional number). When bench hitter limit (2) is reached, caller passes 0 → engine returns bid=0.

Actually, the cleanest approach: The `remainingSlots` record should include BN count. Check if the caller already provides it. If BN is in remainingSlots and is 0, and destination is "BN", return bid=0.

Read strategy-caps.ts and the caller (bid-controller or wherever computeStrategyBidCap is called) to determine the best insertion point. The key behavior: if there is genuinely NO roster slot for this hitter, bid $0 (PASS).
