**FaabTrackerAgent** (`packages/backend/src/agents/faab-tracker.ts`):

Create a class that accepts `Kysely<Database>` and optional `Logger`. Methods:

1. `getSummary(leagueId, teamId)` — Returns FAAB summary:
   - Query `league_settings_version` for FAAB total budget. ESPN stores budget in `settings_json.acquisition_rules`. Default to 100 if not found.
   - Query `league_transaction_event` for all waiver claims by ALL teams. Extract `bidAmount` from `raw_event_json` JSONB. Filter where `event_type = 'waiver'` and `raw_event_json->>'bidAmount'` is not null.
   - Compute `faabRemaining` = totalBudget - sum(won bids for this team). Won bids = transactions where team_id matches and type is waiver/add.
   - Compute `leagueAvgRemaining` = avg remaining across all teams.
   - Compute `spendRate` = totalSpent / weeksElapsed (weeks since season start from first snapshot date).
   - Compute `projectedRunoutWeek` = if spendRate > 0: faabRemaining / spendRate + currentWeek, else null.
   - Compute `weeksRemaining` from current date to end of MLB season (approx week 26, or derive from number of scoring periods in league settings).
   - Return: `{ teamId, faabTotal, faabSpent, faabRemaining, leagueAvgRemaining, spendRate, projectedRunoutWeek, weeksRemaining, willRunOut: projectedRunoutWeek < totalWeeks }`.

2. `getBidHistory(leagueId, teamId)` — Returns bid history:
   - Query `league_transaction_event` where `team_id = teamId` AND `event_type IN ('waiver', 'add')` AND `raw_event_json->>'bidAmount'` is not null.
   - For each transaction: extract bidAmount, players_added (first player ID), look up player name from `player` table.
   - Determine won/lost: If `team_id` matches the transaction's team, it's a won bid. Lost bids aren't directly visible in ESPN data — only store won bids, mark all as 'won'.
   - Compute ROI: Look up player's projection value from `player_projection` (latest run). ROI = projectedValue / bidAmount. Use a simple value heuristic: sum of projected counting stats normalized.
   - Return array of `{ date, playerName, playerId, bidAmount, outcome: 'won', roi }` sorted by date desc.

3. `getSuggestedBid(leagueId, teamId, playerId)` — Returns suggested bid:
   - Get player's projection from `player_projection` (latest fresh run).
   - Get FAAB summary (remaining budget, weeks left).
   - Base bid = player's projected value share of remaining budget. Simple formula: `(playerValue / totalPoolValue) * faabRemaining`, floored at 1, capped at faabRemaining.
   - Adjust for weeks remaining: if < 4 weeks left, multiply by 1.5 (urgency premium). If > 15 weeks left, multiply by 0.7 (patience discount).
   - Return `{ playerId, playerName, suggestedBid, faabRemaining, rationale }`.

**GsPacingAgent** (`packages/backend/src/agents/gs-pacing.ts`):

Create a class accepting `Kysely<Database>` and optional `Logger`. Methods:

1. `getSeasonSummary(leagueId, teamId)` — GS season pacing:
   - GS cap: Default to 200 (standard ESPN roto). Check `league_settings_version.settings_json` for any GS limit override.
   - GS used: Query `team_daily_category_totals` for latest snapshot. Look for category with `stat_key = 'GS'` or approximate from IP (every ~6 IP = 1 GS). If GS stat not tracked, count starts from roster snapshots where pitcher was in active SP slot.
   - Weeks elapsed / total: Compute from first snapshot to season end (~26 weeks).
   - Projected pace: `gsUsed / weeksElapsed * totalWeeks`.
   - Return `{ gsUsed, gsCap, gsRemaining, projectedFinal, pacePerWeek, targetPacePerWeek, paceStatus: 'on_track' | 'burning_fast' | 'too_slow' }`.

2. `getWeeklySummary(leagueId, teamId, weekStartDate?)` — This week's GS:
   - Determine current week boundaries (Monday-Sunday or ESPN scoring period).
   - Query `team_roster_snapshot` for each day in the week. Count distinct pitchers in active SP lineup slots (lineupSlotId for SP positions).
   - Return `{ weekStart, weekEnd, startsUsed, startsRemaining: targetPacePerWeek - startsUsed, pitcherStarts: [{ playerName, playerId, dates: string[] }] }`.

3. `getStartPlan(leagueId, teamId)` — SP start/sit recommendations:
   - Get season summary for pace context.
   - Get team's current roster pitchers from latest `team_roster_snapshot` where roster_slot is SP.
   - For each SP, look up projections from `player_projection`.
   - If pace is burning fast: recommend sitting lowest-projected SPs. Sort by projected K/GS ratio (from research PITCH-03), recommend sitting bottom 1-2.
   - If pace is too slow: recommend starting all SPs, highlight any benched SPs to activate.
   - If on track: rank SPs by K/GS efficiency, recommend starting top N to maintain pace.
   - Return `{ paceStatus, recommendations: [{ playerId, playerName, action: 'start' | 'sit' | 'stream', reason, projectedStats }], alert: string | null }`. Alert is non-null when pace is > 10% off target.

**FAAB routes** (`packages/backend/src/api/faab.ts`):

Endpoints:

**Pitching Usage routes** (`packages/backend/src/api/pitching-usage.ts`):

Same pattern.
