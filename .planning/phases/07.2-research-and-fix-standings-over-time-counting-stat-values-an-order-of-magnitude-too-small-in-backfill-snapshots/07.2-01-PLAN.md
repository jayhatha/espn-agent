Based on the root cause identified in Task 1, implement the appropriate fix. The research identified these likely causes and their fixes:

**If root cause is "statSplitTypeId=5 returns per-game stats, not per-week totals":**
- Check whether `statSplitTypeId=0` (season cumulative) is available. If so, switch to using type 0 and compute per-period delta by subtracting prior period's cumulative from current.
- Alternatively, aggregate ALL `stats[]` entries with `statSplitTypeId=5` for the given `scoringPeriodId` (there may be one per game day).
- Or check if there's a `statSplitTypeId` value that represents weekly totals (e.g., type 1, 2, or 3).

**If root cause is "active roster filter excluding too many players":**
- Fix the `lineupSlotId <= 15` filter. Check which slot IDs are actually in use in the data and adjust the threshold.
- ESPN baseball slots: 0=C, 1=1B, 2=2B, 3=3B, 4=SS, 5-8=OF, 9-10=DH, 11=IF, 12=UTIL, 13=P, 14=SP, 15=RP, 16=BE, 17=IL, 19=NA.

**If root cause is ".find() only capturing first stats entry when multiple exist per player":**
- Replace `.find()` with `.filter()` and aggregate all matching entries.
- Sum stat values across all entries with matching `scoringPeriodId` and `statSplitTypeId`.

**If root cause is "cumulative accumulation broken (previousSnapshotDate not working)":**
- Verify `previousSnapshotDate` is being passed correctly from historical-backfill.ts.
- Check the DB query for prior components — it may be querying the wrong table or wrong conditions.
- Fix the accumulation so that `cumulativeComponents = priorComponents + weekComponents`.

**If root cause is a COMBINATION of issues:**
- Fix all identified issues.
