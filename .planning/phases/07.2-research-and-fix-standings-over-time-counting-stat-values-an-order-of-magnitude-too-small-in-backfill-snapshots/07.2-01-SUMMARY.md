# Phase 07.2 Plan 01: Fix Counting Stat Magnitude Bug in Backfill Summary

**Filter ESPN rate stats (AVG, OBP, SLG, OPS, ERA, WHIP, K9) from per-player component accumulation to prevent nonsensical cumulative rate values polluting backfill standings**

## Performance

- **Duration:** 28 min
- **Started:** 2026-02-22T15:05:13Z
- **Completed:** 2026-02-22T15:33:57Z
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments
- Diagnosed root cause: ESPN per-period stats include rate stat computed values (AVG, OBP, SLG, OPS, ERA, WHIP, K9, WPCT) alongside counting stats, and these were being accumulated as counting components -- producing nonsensical cumulative values like AVG=4.21 after 10 weeks
- Added `if (statInfo.type !== "COUNTING") continue` filter to exclude rate stats from accumulation in `writeCurrentStandingsFromPlayerStats()`
- Verified fix via mock data simulation proving rate stats excluded from components and counting stats correctly accumulated
- Also committed previously uncommitted Phase 07.1 cumulative accumulation logic (previousSnapshotDate, priorComponentsMap) that was in working tree but not yet on the branch
- Live snapshot path (writeCurrentStandings) is completely unmodified -- zero regression risk

## Task Commits

Each task was committed atomically:

1. **Task 1: Diagnose root cause** - No file changes (diagnosed via DB query analysis of existing backfill data)
2. **Task 2: Implement fix and verify** - `b302b69` (fix)

**Plan metadata:** (pending docs commit)

## Files Created/Modified
- `packages/backend/src/agents/snapshot-orchestrator.ts` - Added rate stat type filter in writeCurrentStandingsFromPlayerStats(); added cumulative accumulation via priorComponentsMap
- `packages/backend/src/agents/historical-backfill.ts` - Added previousSnapshotDate tracking across weeks for cumulative accumulation

## Decisions Made
- **Filter at accumulation time, not at ESPN_STAT_MAP level**: Rate stat entries in ESPN_STAT_MAP (type: "RATE") are useful for other code paths (category type detection, formula lookup). Only the accumulation loop needs to skip them.
- **Verified via mock data, not live ESPN**: The 2026 MLB season has not started (current date Feb 22, 2026), so ESPN returns empty roster/stats for all scoring periods. Verified correctness through mock data simulation that proves: (a) before fix, AVG/OBP/SLG/OPS appear in weekComponents with accumulated fractional values; (b) after fix, only counting stats (AB, H, HR, TB, BB, etc.) appear in weekComponents.
