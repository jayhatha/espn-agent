<objective>
Add a backfill pass to the greedy knapsack roster optimizer so every roster slot is filled even when budget is tight or position pools are thin.

Purpose: The current optimizer leaves slots unfilled when the greedy fill loop can't afford players while maintaining $1/slot reserves. This causes the ideal roster panel to show an incomplete team. Additionally, unfilled slots prevent the budget upgrade pass (Phase 4) from running, compounding the problem.

Output: Updated roster-optimizer.ts with canFillSlot helper and backfill pass, updated and new tests proving all-slots-filled guarantee.
</objective>

  <implementation>
    In roster-optimizer.ts, make TWO changes:

    CHANGE 1: Add canFillSlot helper function (near findBestSlot, after DEDICATED_SLOTS constant).

    This is the REVERSE of findBestSlot. findBestSlot takes a player and finds the best slot. canFillSlot takes a specific slot and checks if a player can fill it. Do NOT reuse findBestSlot since its API is inverted.

    ```typescript
    /**
     * Check if a player can fill a specific slot.
     * Reverse of findBestSlot: given a target slot, can this player occupy it?
     */
    function canFillSlot(playerPositions: string[], slot: string): boolean {
      const normalizedPositions = playerPositions.map(normalizePosition);

      if (DEDICATED_SLOTS.has(slot)) {
        // Dedicated slot: player must have exact position match
        return normalizedPositions.includes(slot);
      }

      // Flex slot: player must have a position in FLEX_ELIGIBILITY[slot]
      const eligible = FLEX_ELIGIBILITY[slot];
      if (!eligible) return false;
      return normalizedPositions.some(pos => eligible.includes(pos));
    }
    ```

    CHANGE 2: Add Phase 3b backfill pass after the Phase 3 greedy fill loop and before Phase 4 budget upgrade.

    ```typescript
    if (slotsToFill > 0) {
      // Phase 3b: Backfill -- fill remaining slots with cheapest eligible players.
      // No $1/slot reserve. Force fill even if over budget.
      // Goal: every slot MUST be filled when eligible players exist.
      const usedInRoster = new Set(roster);

      // Iterate SLOT_PRIORITY order so dedicated slots backfill before flex
      for (const slot of SLOT_PRIORITY) {
        const count = remainingSlots.get(slot) ?? 0;
        for (let s = 0; s < count; s++) {
          // Find cheapest eligible player not already in roster
          let cheapest: { player: PoolPlayer; sgp: number } | null = null;
          for (const entry of indexed) {
            if (usedInRoster.has(entry.player)) continue;
            if (!canFillSlot(entry.player.positions, slot)) continue;
            if (!cheapest || entry.player.dollars < cheapest.player.dollars ||
                (entry.player.dollars === cheapest.player.dollars && entry.sgp > cheapest.sgp)) {
              cheapest = { player: entry.player, sgp: entry.sgp };
            }
          }
          if (cheapest) {
            // Place regardless of budget (fill is mandatory)
            roster.push(cheapest.player);
            slotAssignments.push(slot);
            greedyEntries.push({ player: cheapest.player, sgp: cheapest.sgp, slot, rosterIdx: roster.length - 1 });
            usedInRoster.add(cheapest.player);
            totalSGPValue += cheapest.sgp;
            budgetUsed += cheapest.player.dollars;
            remainingBudget -= cheapest.player.dollars;
            slotsToFill--;

            // Decrement slot count
            const c = remainingSlots.get(slot)!;
            if (c > 1) remainingSlots.set(slot, c - 1);
            else remainingSlots.delete(slot);
          }
        }
      }
    }
    ```

    Key design choices:
    - Use SLOT_PRIORITY order so dedicated slots backfill before flex (consistent with greedy)
    - Use canFillSlot helper (not findBestSlot) because we iterate slots and check players, not vice versa
    - Select cheapest eligible player (not most efficient) -- we're in emergency fill mode
    - On tie, prefer higher SGP (get some value)
    - Place even if over remaining budget -- the ideal roster must always be complete
    - Track with usedInRoster Set to avoid double-placement
    - Add backfill entries to greedyEntries so Phase 4 upgrade pass can upgrade them too
    - Do NOT modify Phase 4 condition: it should still check slotsToFill === 0 after backfill
