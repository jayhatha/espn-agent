# Phase 48 Plan 01: Nomination Strategy Rework - Overpricing-Based Scoring

## Objective
Replace trap scoring in nomination strategy with overpricing-based scoring (espn_avg_salary - model_dollar_value) to force league overspending.

## Context
- @packages/extension/lib/engine/nomination-strategy.ts - current trap scoring
- @packages/extension/lib/engine/types.ts - PoolPlayer and NominationRecommendation types
- @packages/extension/lib/engine/index.ts - engine where ESPN ASV is available
- @packages/extension/lib/engine/simulation-worker.ts - calls recommendNomination

## Tasks

### Task 1: Add espnAvgSalary to PoolPlayer type
type="auto"

Add optional `espnAvgSalary?: number` field to the `PoolPlayer` interface in types.ts.

**Done criteria:** Field exists on PoolPlayer interface.

### Task 2: Stamp espnAvgSalary onto PoolPlayers in engine
type="auto"

In engine/index.ts, after building the nameToAsv lookup (already done for bid computation), stamp `espnAvgSalary` onto each PoolPlayer in `allPlayersOpt` before it gets sent to the simulation worker. The FG dollars field stays as-is (model value); espnAvgSalary is the ESPN market price.

**Done criteria:** allPlayersOpt players have espnAvgSalary when ESPN DOM values are available.

### Task 3: Rewrite recommendNomination with overpricing score
type="auto"

Replace the 3-factor trap scoring with overpricing-based scoring:
- Primary: `overpricingScore = (espnAvgSalary - dollars)` where dollars is model value
- Normalize: `normalizedOverpricing = clamp(overpricingScore / 30, 0, 1)` (30 is reasonable max overpricing)
- Secondary: opponent need factor (0-1 normalized)
- Tertiary: my non-need factor (0-1)
- Final: `nominationScore = normalizedOverpricing * 0.6 + opponentNeed * 0.2 + myNonNeed * 0.2`

Update reason strings:
- "Overpriced by $X (ESPN $Y vs model $Z)" when overpricing > 5
- Keep existing opponent/non-need reasons

Fallback: when espnAvgSalary is undefined, fall back to budget drain factor (player.dollars / 50 clamped to 0-1).

**Done criteria:** Function computes overpricing-based scores; reason strings mention overpricing.

### Task 4: Update tests
type="auto"

Update nomination-strategy.test.ts to test overpricing-based scoring:
- Test that players with higher espnAvgSalary relative to dollars score higher
- Test fallback behavior when espnAvgSalary is undefined
- Test reason strings include "Overpriced by"

**Done criteria:** Tests pass with `pnpm --filter extension test`.
