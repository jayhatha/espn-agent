**Bug:** The SP savings calculation in `computeStrategyBidCap` computes ideal spend as `sum(getSpTierCap(0..n))` which assumes SPs are drafted in slot order (SP1=$18, SP2=$12...). But since rank determines tier (user decision #1), a team might draft SP4-tier ($5) arms before SP1-tier ($18) arms. The current code would compute ideal=$18+$12=$30 vs actual=$5+$5=$10, yielding $20 fake savings.

**Fix in strategy-caps.ts:**

1. Add `draftedSpTierCaps?: number[]` to `StrategyCapInput` interface — parallel array to `draftedSpPrices`, where each entry is the rank-based tier cap that SP *should* have cost (e.g., [5, 5] for two SP4-tier arms).

2. In the SP savings reallocation block (around line 264), change:
   ```
   // OLD: slot-position ideal
   for (let s = 0; s < input.draftedSpPrices.length; s++) {
     idealSpSpend += getSpTierCap(s);
   }
   ```
   to:
   ```
   // NEW: per-SP rank-based tier cap
   for (let s = 0; s < input.draftedSpPrices.length; s++) {
     idealSpSpend += input.draftedSpTierCaps?.[s] ?? getSpTierCap(s);
   }
   ```
   This preserves backward compat (falls back to slot-based if no tier caps provided).

3. Apply the same fix to the RP savings reallocation block (around line 292).

4. Update the doc comment on `computeStrategyBidCap` (lines 107-117):
   - Remove "1. Pitcher dampening (x pitcherMultiplier)" — this no longer exists
   - Add "Need multiplier" to the list
   - Update numbering

5. Remove the stale comment block (lines 122-126) that says "Pitcher spending is controlled by SP tier caps... The SGP split (pitcherHitterSplit) already reduces pitcher SGP values in the optimizer" — this is no longer accurate since pitcherHitterSplit is no longer applied to individual SGP values.

**Fix in use-draft-engine.ts:**

6. Around line 133-137, when building `draftedSpPrices`, also build `draftedSpTierCaps`:
   ```typescript
   const draftedSpTierCaps = draftedSPs.map(p => {
     const rank = rankings.find(r => r.playerName.toLowerCase() === p.playerName.toLowerCase())?.externalRank;
     if (rank != null && rank <= 20) return 18;
     if (rank != null && rank <= 30) return 12;
     if (rank != null && rank <= 40) return 10;
     if (rank != null && rank <= 60) return 5;
     return 3; // unranked or rank > 60
   });
   ```
   Pass `draftedSpTierCaps` into the `computeStrategyBidCap` call.

7. Extract the rank-to-tier-cap mapping into a helper function in draft-constants.ts (e.g., `getRankBasedTierCap(rank: number | undefined): number`) to avoid duplicating the rank thresholds. Use it in both strategy-caps.ts (for the current player's tier) and use-draft-engine.ts (for drafted SPs' tier caps).

**Test cases:**

1. **Out-of-order drafting — SP4 before SP1:**
   - Draft 2 SP4-tier arms ($5 cap each) for $5 each
   - `draftedSpPrices: [5, 5]`, `draftedSpTierCaps: [5, 5]`
   - Next SP is SP1-tier (rank=15, cap=$18)
   - Savings should be (5+5) - (5+5) = $0, so tier cap = $18
   - NOT $20 savings from old code (18+12 - 5+5 = 20)

2. **Normal order savings — SP1 got a deal:**
   - Draft SP1-tier for $14 (cap $18), `draftedSpTierCaps: [18]`, `draftedSpPrices: [14]`
   - Next SP is SP2-tier (rank=25, cap=$12)
   - Savings = 18 - 14 = $4
   - Tier cap = 12 + 4 = $16

3. **No savings when overpaid:**
   - Draft SP1-tier for $18 (exact cap), `draftedSpTierCaps: [18]`, `draftedSpPrices: [18]`
   - Next SP is SP3-tier → cap = $10, no savings

4. **RP gets SP savings when 5+ SPs drafted:**
   - Draft 5 SPs with known tier caps and prices
   - RP bid should include savings, capped at $15 total

5. **RP hard cap $15 — savings cannot exceed it:**
   - Even with large SP savings, RP bid never exceeds $15

6. **Ranked SP (top 60) — tier cap is floor AND ceiling:**
   - SP2-tier (rank=25, cap=$12) with rawMaxBid=$5 → bidCap=$12 (floor)
   - SP2-tier (rank=25, cap=$12) with rawMaxBid=$20 → bidCap=$12 (ceiling)

7. **Filler SP (rank > 60) — cap down only, no floor:**
   - Rank=75, cap=$3, rawMaxBid=$2 → bidCap=$2 (no floor)
   - Rank=75, cap=$3, rawMaxBid=$5 → bidCap=$3 (ceiling)

8. **7+ SPs drafted — all further SPs cap at $3:**
   - spCount=7, any rank → tierCap=$3
