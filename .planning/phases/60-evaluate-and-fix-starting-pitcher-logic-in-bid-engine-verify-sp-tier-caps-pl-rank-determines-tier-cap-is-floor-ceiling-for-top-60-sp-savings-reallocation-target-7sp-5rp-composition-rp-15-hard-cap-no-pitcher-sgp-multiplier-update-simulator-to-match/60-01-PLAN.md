**Bug 1 (savings):** The SP savings calculation in `computeStrategyBidCap` computes ideal spend as `sum(getSpTierCap(0..n))` which assumes SPs are drafted in slot order (SP1=$18, SP2=$12...). But since rank determines tier (user decision #1), a team might draft SP4-tier ($5) arms before SP1-tier ($18) arms. The current code would compute ideal=$18+$12=$30 vs actual=$5+$5=$10, yielding $20 fake savings.

**Bug 2 (current player tierCap):** The current-player tierCap in `computeStrategyBidCap` is assigned from `getSpTierCap(input.spCount)` which is slot-based. A PL #28 drafted as the 4th SP gets $5 cap (slot-4) instead of the correct $12 cap (SP2 rank). This MUST be fixed to use rank-based lookup.

**Fix in draft-constants.ts:**

1. Add a `getRankBasedTierCap(rank: number | undefined): number` helper that returns the tier cap based on PL rank:
   - rank 1-20: $18
   - rank 21-30: $12
   - rank 31-40: $10
   - rank 41-60: $5
   - rank > 60, null, or undefined: $3
   Export this helper.

**Fix in strategy-caps.ts:**

2. Add `draftedSpTierCaps?: number[]` to `StrategyCapInput` interface — parallel array to `draftedSpPrices`, where each entry is the rank-based tier cap that SP *should* have cost.

3. **FIX CURRENT-PLAYER TIERCAP (CRITICAL):** In `computeStrategyBidCap`, where the current player's tierCap is assigned (using `getSpTierCap(input.spCount)`), change it to use `getRankBasedTierCap(input.externalRank)` instead. This ensures a PL #28 always gets $12 cap regardless of how many SPs have been drafted. Import `getRankBasedTierCap` from draft-constants.ts. Keep `getSpTierCap(input.spCount)` ONLY as a fallback when externalRank is not available.

4. In the SP savings reallocation block (around line 264), change:
   ```
   // OLD: slot-position ideal
   for (let s = 0; s < input.draftedSpPrices.length; s++) {
     idealSpSpend += getSpTierCap(s);
   }
   ```
   to:
   ```
   // NEW: per-SP rank-based tier cap
   for (let s = 0; s < input.draftedSpPrices.length; s++) {
     idealSpSpend += input.draftedSpTierCaps?.[s] ?? getSpTierCap(s);
   }
   ```
   This preserves backward compat (falls back to slot-based if no tier caps provided).

5. Apply the same fix to the RP savings reallocation block (around line 292).

6. Update the doc comment on `computeStrategyBidCap` (lines 107-117):
   - Remove "1. Pitcher dampening (x pitcherMultiplier)" — this no longer exists
   - Add "Need multiplier" to the list
   - Update numbering

7. Remove the stale comment block (lines 122-126) that says "Pitcher spending is controlled by SP tier caps... The SGP split (pitcherHitterSplit) already reduces pitcher SGP values in the optimizer" — this is no longer accurate since pitcherHitterSplit is no longer applied to individual SGP values.

**Fix in use-draft-engine.ts:**

8. Around line 133-137, when building `draftedSpPrices`, also build `draftedSpTierCaps`:
   ```typescript

     const rank = rankings.find(r => r.playerName.toLowerCase() === p.playerName.toLowerCase())?.externalRank;
     return getRankBasedTierCap(rank);
   });
   ```
   Import `getRankBasedTierCap` from draft-constants.ts.
   Pass `draftedSpTierCaps` into the `computeStrategyBidCap` call.
