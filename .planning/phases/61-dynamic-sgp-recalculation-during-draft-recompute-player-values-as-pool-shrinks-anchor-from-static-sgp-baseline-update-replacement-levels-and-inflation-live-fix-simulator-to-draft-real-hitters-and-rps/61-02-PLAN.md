    **Fix 1: RP cap conditional on pitcher total**

    Find the RP hard cap guard in `computeOurBid()` (around line 506):
    ```typescript
    if (team.rpCount >= 5) return 0;
    ```

    Replace with a conditional cap that allows more RPs when SP slots weren't filled:
    ```typescript
    // Allow more RPs if SP count is below 7 (pitcher slots still need filling)
    const maxRPs = Math.max(5, 12 - team.spCount);
    if (team.rpCount >= maxRPs) return 0;
    ```

    This means: if we only drafted 5 SPs, we can draft up to 7 RPs to fill the remaining 12 pitcher slots. The cap only bites at 5 when we have the full 7 SPs. Note: `team.spCount` must be tracked in TeamState. If it isn't already, add it:
    - Add `spCount: number` to the `TeamState` interface (around line 225)
    - Initialize it to `0` in the team state initialization (around line 693)
    - Increment it in the winner-processing block: after `if (isSP(player)) { teams[winner].spCount++; }` (near where `rpCount` is incremented, around line 877)

    **Fix 2: SP/RP distinction in mode roster display**

    In `assignSlot()` for pitchers (around line 602-608), distinguish SP from RP in the returned slot string:
    ```typescript
    // Was: if ((slots["P"] ?? 0) > 0) { slots["P"]--; return "P"; }
    // Becomes:
    if ((slots["P"] ?? 0) > 0) {
      slots["P"]--;
      return isPitcherSP ? "SP" : "RP"; // use isCurrentPlayerSP flag passed in
    }
    ```

    BUT: `assignSlot()` currently takes `positions: string[]` not the full player. The cleanest approach is to add an `isSP: boolean` parameter to `assignSlot()`:
    ```typescript
    function assignSlot(
      positions: string[],
      slots: Record<string, number>,
      isPitcher: boolean,
      team?: TeamState,
      isStartingPitcher?: boolean  // NEW optional param
    ): string | null {
    ```

    Then in the pitcher branch:
    ```typescript
    if (isPitcher) {
      if ((slots["P"] ?? 0) > 0) {
        slots["P"]--;
        return isStartingPitcher ? "SP" : "RP";  // distinguish for display
      }
      if ((slots["BN"] ?? 0) > 0 && (!team || team.benchPitchers < 3)) {
        slots["BN"]--;
        if (team) team.benchPitchers++;
        return isStartingPitcher ? "SP-BN" : "RP-BN";  // distinguish bench too
      }
      return null;
    }
    ```

    Update the `SLOT_DISPLAY_ORDER` to include the new slot strings:
    ```typescript
    const SLOT_DISPLAY_ORDER = ["C", "1B", "2B", "SS", "3B", "MI", "CI", "OF", "UTIL", "SP", "RP", "SP-BN", "RP-BN", "BN"];
    ```

    Update all call sites of `assignSlot()` to pass the new parameter:
    - In the winner-processing block (around line 851): `assignSlot(player.positions, teams[winner].slotsRemaining, player.isPitcher, teams[winner], isSP(player))`

    **Fix 3: Add bench hitter diagnostic output**

    In the post-simulation summary section, add:
    ```typescript
    const meanBenchHitters = mean(results.map(r => r.benchSplit.hitters));
    const meanBenchPitchers = mean(results.map(r => r.benchSplit.pitchers));
    const meanSPs = mean(results.map(r => r.spDrafted));  // need to add spDrafted to result
    const meanRPs = mean(results.map(r => r.rpDrafted));
    const meanFilledSlots = mean(results.map(r => r.filledSlots));  // need to add filledSlots to result

    console.log(`\nRoster Composition (mean across ${NUM_SIMS} sims):`);
    console.log(`  SPs: ${meanSPs.toFixed(1)} | RPs: ${meanRPs.toFixed(1)}`);
    console.log(`  Bench hitters: ${meanBenchHitters.toFixed(1)}/2 | Bench pitchers: ${meanBenchPitchers.toFixed(1)}/3`);

    ```

    Add `spDrafted` and `filledSlots` to the `SimResult` type and populate them:
    - `spDrafted: number` — count of SPs on my team at end of draft (`myTeam.spCount`)
    - `filledSlots: number` — count of non-null slot assignments for my team (sum of used slots from slotsRemaining vs starting slots)

    For `filledSlots`, the simplest computation: 28 (total roster) minus the sum of remaining slots in `myTeam.slotsRemaining` at end of draft:
    ```typescript
    const filledSlots = 28 - Object.values(myTeam.slotsRemaining).reduce((s, v) => s + v, 0);
    ```

    Note: The `SimResult` interface is defined around line 575. The `benchSplit` field already exists. Add `spDrafted` and `filledSlots` to it. The return statement in `simulateAuction()` (around line 955) must be updated to include the new fields.
