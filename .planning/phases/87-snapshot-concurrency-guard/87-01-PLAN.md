# Plan 87-01: Manual Snapshot Concurrency Guard

## Goal

Route `POST /api/leagues/:leagueId/snapshot` through BullMQ with the same deterministic jobId used by `scheduleDailySnapshots()`, preventing concurrent executions for the same league+date.

## Changes

### packages/backend/src/api/leagues.ts

- Added `import { snapshotQueue } from "../workers/snapshot-worker.js"`
- Replaced direct `orchestrator.executeSnapshot()` call with `snapshotQueue.add(jobId, data, opts)`
- jobId pattern: `snapshot-${leagueId}-${today}` (matches scheduler)
- Returns `202 { queued: true, jobId }` on success
- Returns `202 { queued: false, reason: "duplicate", jobId }` when BullMQ deduplicates (job already exists)
- Added `GET /api/leagues/:leagueId/snapshot/status/:jobId` endpoint to poll job state

## Verification

- `SnapshotOrchestratorAgent` import retained for bootstrap snapshot handlers at connect/reinit endpoints (lines ~270 and ~849) which run fire-and-forget initial snapshots
- TypeScript: 0 errors in leagues.ts (pre-existing errors in other files unaffected)

## UAT

- POST /snapshot returns 202 with jobId
- Duplicate POST within same day returns `{ queued: false, reason: "duplicate" }`
- GET /snapshot/status/:jobId returns job state (waiting/active/completed/failed)
