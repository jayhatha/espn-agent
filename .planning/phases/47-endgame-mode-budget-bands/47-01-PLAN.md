# Endgame Mode & Budget Bands

## Objective

Add endgame mode activation when budget <= $20 with value_per_dollar scoring, and enforce hitter/pitcher budget allocation bands in the draft engine signals.

## Context

- @packages/extension/lib/engine/types.ts - signal types
- @packages/extension/lib/engine/budget-curve.ts - budget pressure tracking
- @packages/extension/lib/auto-bid-controller.ts - bidding logic with 4 paths

## Tasks

### Task 1: Extend BudgetCurveSignal with endgame and budget band fields
type="auto"

Add to BudgetCurveSignal in types.ts:
- `endgameMode: boolean` (true when budget <= $20)
- `hitterBudgetTarget: { min: number; max: number }` (185-205)
- `pitcherBudgetTarget: { min: number; max: number }` (55-70)
- `benchBudget: number` (5)
- `hitterSpent: number` (tracked from roster state)
- `pitcherSpent: number` (tracked from roster state)

**Done:** types.ts compiles with new fields.

### Task 2: Compute endgame and budget band signals in budget-curve.ts
type="auto"

Update computeBudgetCurve to:
- Accept hitterSpent/pitcherSpent parameters
- Set endgameMode = true when remainingBudget <= 20
- Return budget band targets and spending tracking
- Log endgame activation

**Done:** computeBudgetCurve returns all new fields.

### Task 3: Wire budget band params through engine caller
type="auto"

Find where computeBudgetCurve is called (engine/index.ts) and pass hitterSpent/pitcherSpent from roster state. Compute hitter/pitcher spending from myRoster drafted players.

**Done:** Engine passes spending data to budget curve.

### Task 4: Add endgame mode logic to auto-bid-controller
type="auto"

In evaluateAndBid(), when budgetCurve.endgameMode is true:
- Calculate value_per_dollar = (idealMatch SGP or ranking value) / currentBid
- Tighten bid caps: only bid on high value_per_dollar players
- Prefer: breakout hitters (high projected stats), cheap OF, K pitchers
- Avoid: catchers when C slot is filled (already exists), weak OPS players
- Log: `[AutoBid] ENDGAME MODE activated ($X remaining)`

**Done:** Endgame logic modifies bidding behavior when budget <= $20.

### Task 5: Build verification
type="auto"

Run `pnpm --filter extension build` and verify no type errors.

**Done:** Extension builds cleanly.

## Verification

- `pnpm --filter extension build` passes
- BudgetCurveSignal has endgameMode, budget band fields
- computeBudgetCurve returns endgameMode=true when budget<=20
- evaluateAndBid applies endgame bid dampening

## Success Criteria

- END-01: Endgame mode activates at budget <= $20
- END-02: Budget allocation bands defined (H: 185-205, P: 55-70, BN: 5)
- END-03: Endgame preferences (breakout hitters, cheap OF, K pitchers; avoids backup C, weak OPS)
