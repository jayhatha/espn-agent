# Phase 49 Plan 01: Positional Weights & SP Tiers

## Objective

Add positional priority weights that boost bid ceilings for scarce positions, SP tier caps that limit pitcher spending based on how many SPs are already drafted, and 200 GS cap awareness in pitcher valuation.

## Context

- @packages/extension/lib/engine/roster-optimizer.ts -- slot priority, greedy knapsack
- @packages/extension/lib/engine/types.ts -- signal types
- @packages/extension/lib/auto-bid-controller.ts -- bidding paths with pitcher dampening
- @packages/extension/lib/engine/bid-optimizer.ts -- SGP-based bid optimization

## Tasks

<task id="1" type="auto">
<name>Add constants for positional weights, SP tier caps, and GS cap</name>
<detail>
Create a new constants file at packages/extension/lib/engine/draft-constants.ts with:

1. POSITIONAL_WEIGHTS: Record<string, number> mapping positions to bid bonuses
   SS: 4, OF: 3, "3B": 3, "1B": 2, "2B": 2, C: 1, SP: 0, RP: 0, P: 0, DH: 2, UTIL: 0, BN: 0

2. SP_TIER_CAPS: array of { tier, max } for SP spending limits
   Tier 1: max 18, Tier 2: max 12, Tier 3: max 10, Tier 4: max 5, Tier 5: max 3

3. GS_CAP = 200 constant for games started awareness

4. Helper functions:
   - getPositionalWeight(positions: string[]): number -- returns max weight from player positions
   - getSpTierCap(spCount: number): number -- returns max bid for the next SP tier slot
</detail>
<done>Constants file exists with all three constants and both helper functions exported. TypeScript compiles.</done>
</task>

<task id="2" type="auto">
<name>Apply positional weights to bid caps in auto-bid-controller</name>
<detail>
In auto-bid-controller.ts, after the bid cap is computed (after pitcher dampening and catcher dampening), add positional weight adjustment:

1. Import getPositionalWeight from draft-constants
2. Look up the player's positions from the ranking record
3. Add the positional weight to autoBidCap
4. Log the adjustment in capSource

This means a SS with a $10 cap becomes $14, an OF with $10 becomes $13, etc.
</detail>
<done>Positional weight is added to autoBidCap after existing dampening. Log messages show the adjustment.</done>
</task>

<task id="3" type="auto">
<name>Apply SP tier caps in auto-bid-controller</name>
<detail>
In auto-bid-controller.ts, when the nominated player is an SP:

1. Import getSpTierCap from draft-constants
2. Count SPs already on myRoster (state.myRoster filtered by positions containing "SP")
3. Look up the tier cap for the next SP slot
4. Cap autoBidCap at the tier max (take the minimum)
5. Log the SP tier cap application

This ensures SP1 can go up to $18, SP2 up to $12, SP3 up to $10, etc.
</detail>
<done>SP tier caps applied when nominated player is SP. Bid cap is clamped to tier max. Log shows tier and cap.</done>
</task>

<task id="4" type="auto">
<name>Add GS cap awareness to pitcher valuation commentary</name>
<detail>
In draft-constants.ts, add a GS_CAP_NOTE documenting that the 200 GS cap means SP slots are limited and high-K relievers can be valuable.

In auto-bid-controller.ts, when evaluating SPs beyond tier 3 (SP4, SP5+), add a log note about GS cap awareness:
- If spCount >= 3, log that GS cap suggests preserving budget for high-K relievers
- This is informational for now; the tier caps already enforce spending limits
</detail>
<done>GS_CAP constant documented. SP4+ evaluations log GS cap awareness note.</done>
</task>
