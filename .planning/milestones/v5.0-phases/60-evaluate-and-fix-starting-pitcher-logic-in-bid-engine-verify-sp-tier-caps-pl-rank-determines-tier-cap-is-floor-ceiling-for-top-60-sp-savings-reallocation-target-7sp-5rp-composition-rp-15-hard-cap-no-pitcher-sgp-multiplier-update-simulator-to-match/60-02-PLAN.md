**1. Fix current-player tierCap in simulator's `computeOurBid` (CRITICAL):**

The simulator's `computeOurBid` function assigns the current player's tierCap using `getSpTierCap(spCount)` which is slot-based. A PL #28 drafted as the 4th SP gets $5 cap (slot-4) instead of the correct $12 cap (SP2 rank).

Fix: Derive tierCap from plRank directly in `computeOurBid`. Replace:
```
tierCap = getSpTierCap(spCount);
```
with:
```
const plRank = plRankMap.get(player.normalizedName);
if (plRank != null && plRank <= 20) tierCap = 18;
else if (plRank != null && plRank <= 30) tierCap = 12;
else if (plRank != null && plRank <= 40) tierCap = 10;
else if (plRank != null && plRank <= 60) tierCap = 5;
else tierCap = 3;
```

Run 2000 simulations and analyze the output for pitching-vs-hitting conflicts. The audit should examine these specific interaction points:

**Conflict areas to investigate (by reading code + analyzing sim output):**

1. **Hitter budget cap ($220) vs SP tier commitment:**
   The hitter cap limits hitter spending to $220, leaving $40 for pitching. But SP tier caps alone sum to $18+$12+$10+$5+$5+$3+$3 = $56 for 7 SPs, plus 5 RPs at ~$3-15 each. If the engine hits the hitter cap early, does it have enough budget left for quality pitching? Conversely, if SP tier floor pushes pitcher spend above $40, does the hitter cap need adjustment?

2. **Budget flush vs SP tier floor:**
   Budget flush boosts bids when few slots remain and excess budget exists. If remaining slots are P slots waiting for SPs, budget flush could push hitter bids up (spending budget that should be reserved for SP tier floors). Does budget flush respect the fact that remaining P slots have minimum tier costs?

3. **Positional weights vs pitcher valuation:**
   Positional weights (+1 to +4) boost hitter bids but pitchers get no weight bonus. This creates asymmetric pressure — hitters get bid up while pitchers stay at tier cap levels. Is this intentional? Does it cause hitters to consume more budget than the $220 cap intends?

4. **Endgame dampening vs SP tier floor:**
   When endgame activates (budget <= $20), all bids get 30% reduction. But SP tier caps are applied BEFORE endgame dampening. For a ranked SP with $12 tier floor: bid=$12, then endgame makes it $9. This violates the tier floor commitment. Should ranked SPs be exempt from endgame dampening?

**Analysis method:**
- Run 2000 sims with `--sims 2000`
- Look at average hitter spend vs pitcher spend
- Look at how often SPs are drafted below their tier floor
- Look at how often budget flush fires on hitter picks when P slots remain
- Check endgame SP purchases

**Output:** Document findings and recommendations in the SUMMARY.md file under a `## Pitching vs Hitting Conflicts` section. For each conflict found, describe: the interaction, when it fires, impact on draft outcome, and recommended resolution (code change, constant tweak, or "acceptable tradeoff").

No code changes in this task — just analysis and documentation. If critical bugs are found (e.g., endgame dampening breaking tier floors), note them as follow-up items.
