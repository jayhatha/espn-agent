  <name>Task 1: Fix simulateTradeImpact() component math and category key alignment</name>
  <files>packages/backend/src/agents/trade-recommendation.ts</files>
  <action>
Refactor `simulateTradeImpact()` to fix two issues:

**Issue 1: Category ID vs Stat Key mismatch**
The method uses `category.stat_key` as the map key for `teamCategoryValues` and `userTeamCategories`, but `team_daily_projected_category` rows use `category_id`. These differ (e.g., category_id="0" vs stat_key="R"). Fix by using `category_id` consistently as the map key when reading from and writing to `teamCategoryValues`. Update the loop that reads `allTeamProjections` to use `proj.category_id` and the loop that processes categories to look up by `category.category_id`.

**Issue 2: JSON.parse on already-parsed JSONB**
In `isCategoryRelevant()` and `getProjectedCategoryValue()`, the code calls `JSON.parse(projection.stat_components_json)`. However, `getPlayerProjections()` fetches via Kysely which returns JSONB as objects. The `JSON.parse()` call works by accident (parsing an object returns itself) but is incorrect. Change to cast directly: `const components = projection.stat_components_json as StatComponents`.

Similarly, in the rate stat branch of `simulateTradeImpact()`, lines like `JSON.parse(proj.stat_components_json) as Record<string, number>` should be changed to `proj.stat_components_json as StatComponents`.

**Issue 3: Align rate stat component math with waiver pattern**
In `simulateTradeImpact()`, the rate stat branch currently builds `adjustedComponents` by iterating over give/receive players and subtracting/adding to the current projected components. This is correct in principle but should match the waiver agent's proven pattern more closely:

1. Start with `projected_components_json` from `team_daily_projected_category` (already in `current.components`)
2. For each give player whose projection is category-relevant: subtract their stat components
3. For each receive player whose projection is category-relevant: add their stat components
4. Call `calculateFinalRate(category.formula_id, {}, adjustedComponents)` with empty first arg (all components already combined)

Ensure the `isCategoryRelevant()` helper uses `PITCHING_STAT_KEYS.has(category.stat_key)` to filter correctly (batter projections only affect batting categories, pitcher projections only affect pitching categories).
