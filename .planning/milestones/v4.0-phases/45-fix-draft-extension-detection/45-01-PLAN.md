# Phase 45 Plan 01: Fix Draft Extension Team Detection

## Objective
Fix extension team/pick detection so myRoster is populated accurately using hardcoded config as primary source, with DOM detection as validation.

## Context
- `parsePickElement` sets `pick.teamId` to grid column string (e.g., "5"), NOT ESPN team ID
- `content.tsx` sets `myTeamId` from URL param (e.g., "13") which IS an ESPN team ID
- So `pick.teamId ("5") !== myTeamId ("13")` always fails to match
- `detectMyTeam()` may fail if pick train not rendered yet, leaving `myGridColumn` null
- `getTeamColumnMapping()` in dom-observers.ts maps grid column -> ESPN team ID

## Tasks

### Task 1: Use DEFAULT_TEAM_ID as primary myTeamId
type="auto"

Import `DEFAULT_TEAM_ID` in content.tsx and use it as the primary team ID source instead of the URL parameter.

**Changes:**
1. Add `DEFAULT_TEAM_ID` to the import from `@espn-fantasy/shared`
2. Change `myTeamId: teamId ?? "user"` to `myTeamId: String(DEFAULT_TEAM_ID)` in `initializeDraft`
3. Log that hardcoded config is being used

**Done when:** `initializeDraft` uses `DEFAULT_TEAM_ID` as the primary source

### Task 2: Compute myGridColumn from team column mapping
type="auto"

After `initializeDraft`, use `getTeamColumnMapping()` to find which grid column corresponds to DEFAULT_TEAM_ID. This replaces reliance on `detectMyTeam()` for the grid column.

**Changes:**
1. Import `getTeamColumnMapping` from dom-observers
2. After initializeDraft, call `getTeamColumnMapping()` and find the column where `entry.teamId === String(DEFAULT_TEAM_ID)`
3. Set `myGridColumn` from this mapping
4. If mapping fails (dropdown not ready), keep the detectMyTeam() result as fallback
5. Add retry logic: if myGridColumn is still null after 3s, retry the mapping

**Done when:** myGridColumn is computed from dropdown mapping, not just from pick train position

### Task 3: Use hardcoded config as primary for detectLeagueConfig
type="auto"

Change `detectLeagueConfig()` in content.tsx to use hardcoded defaults as primary instead of DOM detection. DOM detection becomes validation only.

**Changes:**
1. Instead of calling detectLeagueConfig() and falling back to defaults, USE defaults directly as primary
2. Still call detectLeagueConfig() but only for validation/logging (compare detected vs hardcoded)
3. Log mismatches as warnings but don't override hardcoded values

**Done when:** cachedLeagueConfig always starts with hardcoded defaults, DOM detection validates only

### Task 4: Build verification
type="auto"

Run the extension build to verify no TypeScript or bundling errors.

**Done when:** `pnpm --filter extension build` exits cleanly

## Verification
- Extension build passes without errors
- `initializeDraft` uses `String(DEFAULT_TEAM_ID)` not URL param
- `myGridColumn` computed from `getTeamColumnMapping()` with retry
- Config detection uses hardcoded defaults as primary

## Success Criteria
1. Extension loads hardcoded league config before DOM detection runs
2. myTeamId is always "13" (from DEFAULT_TEAM_ID), not from URL param
3. myGridColumn is computed from dropdown mapping (column where teamId=13)
4. Config detection uses hardcoded values with DOM validation
