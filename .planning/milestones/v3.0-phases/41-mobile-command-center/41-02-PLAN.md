In `packages/backend/src/api/draft-live.ts`:

1. Add a `broadcastToMobile` helper function inside `draftLiveRoutes` (after the `mobileClients` declaration):
```typescript
function broadcastToMobile(msg: Record<string, unknown>) {
  const str = JSON.stringify(msg);
  for (const client of mobileClients) {
    if (client.readyState === 1) client.send(str);
  }
}
```

2. In the extension connect handler (role === "extension" block, after `extensionSocket = socket`), broadcast to all existing mobile clients:
```typescript
broadcastToMobile({ type: "EXTENSION_STATUS", connected: true, ts: Date.now() });
```

3. In the extension `socket.on("close")` handler, AFTER setting `extensionSocket = null`, broadcast:
```typescript
broadcastToMobile({ type: "EXTENSION_STATUS", connected: false, ts: Date.now() });
```

4. In the extension `socket.on("error")` handler, AFTER setting `extensionSocket = null`, broadcast:
```typescript
broadcastToMobile({ type: "EXTENSION_STATUS", connected: false, ts: Date.now() });
```

5. When a new mobile client connects (the `else` block for non-extension connections), BEFORE sending the latestSnapshot, immediately send the current extension status to just that socket:
```typescript
socket.send(JSON.stringify({
  type: "EXTENSION_STATUS",
  connected: extensionSocket !== null,
  ts: Date.now(),
}));
```
This prevents the race condition described in research pitfall 2 — mobile connecting before extension would never learn the extension status.

6. Add `ExtensionStatusMessage` to the message type definitions at the top:
```typescript
interface ExtensionStatusMessage {
  type: "EXTENSION_STATUS";
  connected: boolean;
  ts: number;
}
```
