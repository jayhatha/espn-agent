# Plan 42-01: Phase-aware queue strategy with bidding guard

## Objective

Make `populateQueue()` phase-aware: early draft queues expensive non-targets (poison pills) to drain opponent budgets, later draft queues our core/value targets. Add a bidding guard so queue population only runs when idle — not during active bidding.

## Context

**Current behavior:**
- `populateQueue()` (auto-bid-controller.ts:573) builds candidates from two sources in fixed order:
  1. Nomination strategy trap scores (sorted by trapScore desc) — these are expensive non-needs
  2. Ideal roster non-drafted players — these are our actual targets
- It always prioritizes trap scores over targets regardless of draft phase
- It has a guard for user's turn (Select buttons) but no guard for active bidding

**What needs to change:**
1. Add bidding guard: skip queue population when `form.bidding-form__default` exists in DOM (active bidding) OR when `currentAuctionPlayer` is set and we haven't been outbid
2. Add roster fill % calculation and use it to blend candidate sources
3. Early draft (≤30% roster filled): trap scores first, then targets as fallback (current behavior)
4. Late draft (>30% roster filled): own targets first, then trap scores as fallback (inverted)

## must_haves

- [ ] populateQueue() skips when a bidding form is present in the DOM
- [ ] Early draft prioritizes trap-score candidates (poison pills)
- [ ] Late draft prioritizes ideal roster targets (core/value)
- [ ] Transition is based on roster fill percentage, not abrupt

Add a new static constant:


Then modify the candidate building to be phase-aware. Replace the current fixed-order candidate building block (lines ~628-645) with:

```typescript
type Candidate = { name: string; source: "simulation" | "idealRoster" };
const trapCandidates: Candidate[] = [];
const targetCandidates: Candidate[] = [];

// Trap candidates from nomination strategy (expensive non-needs)
const nominationStrategy =
  this.lastEngineSignals?.simulation?.nominationStrategy;
if (nominationStrategy && nominationStrategy.length > 0) {
  for (const rec of nominationStrategy) {
    trapCandidates.push({ name: rec.playerName, source: "simulation" });
  }
}

// Target candidates from ideal roster (our core/value players)
const idealPlayers = this.lastEngineSignals?.idealRoster?.players ?? [];
for (const p of idealPlayers) {
  if (!p.isDrafted) {
    targetCandidates.push({ name: p.name, source: "idealRoster" });
  }
}

// Phase-aware ordering:
// Early draft (≤30% filled): poison pills first, then targets
// Late draft (>30% filled): our targets first, then poison pills
const candidates: Candidate[] = isEarlyDraft
  ? [...trapCandidates, ...targetCandidates]
  : [...targetCandidates, ...trapCandidates];

logger.log(
  `[AutoQueue] Draft phase: ${isEarlyDraft ? "early" : "late"} (${(rosterFillPct * 100).toFixed(0)}% filled, ${state.myRoster.length}/${AutoBidController.TARGET_ROSTER_SIZE} slots). Strategy: ${isEarlyDraft ? "poison pills first" : "own targets first"}`,
);
```

This replaces the existing candidate building block. The rest of the function (matching candidates to rankings, finding buttons, search-and-queue) stays unchanged.
