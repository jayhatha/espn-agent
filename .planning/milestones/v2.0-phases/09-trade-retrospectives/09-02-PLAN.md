**Part A: Add bootstrap confidence interval method to TransactionImpactAgent**

Add a new public method:

```typescript
async bootstrapConfidenceIntervals(
  leagueId: number,
  season: number,
  teamId: number,
  numBootstraps: number = 200,
): Promise<void>
```

This method updates existing `transaction_impact` rows with CI data. Algorithm:

1. Get all `transaction_impact` rows for this team/league/season
2. For each impact row, get the original player period stats used in its computation:
   - Gained player: `player_period_stats` rows from effective_date to final snapshot, filtered to this team
   - Lost player (if any): `player_period_stats` rows from effective_date to final snapshot (anywhere)
3. For each of `numBootstraps` iterations:
   - Resample the gained player's period stats WITH REPLACEMENT (same count, random selection with duplication)
   - Resample the lost player's period stats WITH REPLACEMENT
   - Sum resampled components for gained and lost
   - Build counterfactual team components: actual - resampled_gained + resampled_lost
   - Recompute rate stats from components using `calculateFinalRate`
   - Re-rank league, compute roto points delta
   - Record the delta for this bootstrap sample
4. Sort bootstrap deltas, extract 2.5th percentile (ci_low) and 97.5th percentile (ci_high)
5. Flag `is_uncertain = true` if CI crosses zero (ci_low < 0 AND ci_high > 0) OR if CI width > 2x the point estimate
6. Update the `transaction_impact` row with ci_low, ci_high, is_uncertain

EFFICIENCY: Use 200 bootstraps (not 1000) to stay practical. Pre-load all player period stats for the team upfront. The bootstrap resamples from in-memory arrays, only the final ranking computation touches the team components map.

Note: Bootstrap CI uses the simple counterfactual (not Shapley) for each move individually. This is computationally feasible and gives per-move uncertainty. Shapley-level bootstrap would require 200 x 500 x N_moves evaluations which is prohibitive.
