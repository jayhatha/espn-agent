**Step A: Add `computeSGPFactors` method**

Add a new method that computes per-category SGP (Standings Gain Points) factors from the league's final standings:

```typescript
private computeSGPFactors(
  teamFinalComponents: Map<number, Record<string, number>>,
  categories: CategoryConfig[],
): Record<string, number>
```

For counting stats: SGP factor = average absolute gap between adjacent teams when sorted by that category. For rate stats: SGP factor = standard deviation of team values for that category. Guard against zero (use 1.0 as minimum SGP factor to prevent division-by-zero).

**Step B: Add `computeReplacementLevel` method**

```typescript
private async computeReplacementLevel(
  leagueId: number,
  season: number,
  finalSnapshotDate: string,
  position: string,
): Promise<Record<string, number>>
```

Compute replacement-level production for a position:
1. Get all players at that position from `player_period_stats` for the season
2. Sum each player's total production (components) across the season
3. Sort players by total counting stat production (R+HR+RBI for hitters, K+W+SV for pitchers)
4. Identify the number of rostered players at this position (numTeams x slotsPerPosition from league settings)
5. Replacement level = average production of players ranked just outside the rostered pool (ranks N+1 through N+3)
6. If insufficient data, return empty record (degrade gracefully)

**Shapley computation for a single team's moves:**

```typescript
private async computeTeamShapleyValues(
  leagueId: number,
  teamId: number,
  movePairs: MovePair[],
  draftComponents: Record<string, number>,
  teamFinalComponents: Map<number, Record<string, number>>,
  categories: CategoryConfig[],
  numTeams: number,
  actualRotoPoints: Map<number, number>,
  finalSnapshotDate: string,
  numSamples: number,
): Promise<Map<number, number>>  // movePairIndex -> shapleyValue
```

EFFICIENCY OPTIMIZATION: Pre-load ALL player contributions for this team upfront into a `Map<string, Record<string, number>>` keyed by `"gained_{playerId}"` and `"lost_{playerId}"`. This avoids N*1000 database queries. Load once, reference from memory during sampling.

For each of `numSamples` (default 500 -- not 1000, to keep computation under 30 seconds for 50 moves) iterations:
1. Create a random permutation of movePairs (Fisher-Yates shuffle)
2. For each move in the permutation, track its index in the original movePairs array
3. Walk through the permutation. For each move at position k:
   - Build "coalition components" = draft-day roster + contributions from moves 0..k-1 in this permutation
   - Compute roto points WITH this move added to coalition
   - Compute roto points WITHOUT this move (just the coalition)
   - Marginal contribution = with - without
4. Record each move's marginal contribution for this sample

After all samples, each move's Shapley value = average of its marginal contributions across all samples.

**Building coalition components efficiently:**

Instead of recomputing from scratch for each coalition, maintain a running component total:
- Start with draft-only components
- For each move in the permutation order, incrementally add its gained player's contribution and subtract its lost player's counterfactual
- Before adding the target move, snapshot = "without". After adding = "with". Delta = marginal contribution.
- Recompute rate stats from components and re-rank the league for each snapshot.

For rate stat recomputation in coalitions, reuse the existing pattern from `computeSingleMoveImpact` (lines 602-624 in current code) that builds `_val_{statKey}` entries from components using `calculateFinalRate`.

**Step D: Compute SGP category impacts**

For each move, after Shapley computation, also compute SGP-normalized category impacts:
