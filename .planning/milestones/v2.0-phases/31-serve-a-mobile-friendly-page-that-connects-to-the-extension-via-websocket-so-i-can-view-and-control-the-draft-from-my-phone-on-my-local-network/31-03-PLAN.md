  <name>Task 1: Create useDraftLiveSocket WebSocket hook with reconnect</name>
  <files>packages/frontend/src/app/draft/live/useDraftLiveSocket.ts</files>
  <action>
Create a "use client" module at `packages/frontend/src/app/draft/live/useDraftLiveSocket.ts`:

1. Export `useDraftLiveSocket(wsUrl: string)` hook returning `{ state, engineSignals, connected, sendControl }`.

2. State shape:
   - `state`: `{ currentAuctionPlayer, myRosterCount, remainingBudget, autoMode, pitcherHitterSplit, draftFormat, allPicksCount, currentPick } | null`
   - `engineSignals`: `{ inflation, budgetCurve, alerts, optimization, simulation, remainingSlots, computeTimeMs } | null`
   - `connected`: boolean
   - `sendControl`: `(action: string, payload?: unknown) => void`

3. Implementation:
   - Use `useRef<WebSocket | null>` for the socket reference.
   - Use `useState` for `state`, `engineSignals`, `connected`.
   - `useEffect` depending on `wsUrl`:
     - If wsUrl is empty, return early.
     - Create WebSocket: `new WebSocket(wsUrl)`.
     - On "open": set `connected(true)`.
     - On "close": set `connected(false)`. Schedule reconnect after 3 seconds via setTimeout. Clear on cleanup.
     - On "message": parse JSON. If `msg.type === "STATE_SNAPSHOT"`:
       - If `msg.payload`, set `state(msg.payload)`.
       - If `msg.engineSignals`, set `engineSignals(msg.engineSignals)`.
     - On "error": log to console (close handler will trigger reconnect).
     - Cleanup: close the WebSocket, clear reconnect timeout.

4. `sendControl` function:
   ```typescript
   const sendControl = useCallback((action: string, payload?: unknown) => {
     if (wsRef.current?.readyState === WebSocket.OPEN) {
       wsRef.current.send(JSON.stringify({ type: "CONTROL", action, payload }));
     }
   }, []);
   ```

5. Use `useCallback` for sendControl to maintain stable reference.

<task type="auto">
  <name>Task 2: Create mobile draft companion page with touch-optimized UI</name>
  <files>packages/frontend/src/app/draft/live/page.tsx</files>
  <action>
Create a "use client" page at `packages/frontend/src/app/draft/live/page.tsx`. This is the mobile companion page.

**URL Configuration (top of page):**
- Initialize WS URL from localStorage key `"draft-live-ws-url"`.
- Default: `ws://${window.location.hostname}:3001/draft/live?role=mobile` (auto-detects LAN IP from the page URL origin — if the phone loads `http://192.168.1.42:3000/draft/live`, the WS URL defaults to `ws://192.168.1.42:3001/draft/live?role=mobile`).
- Show an editable URL input field in a collapsible "Connection" section at the top. On change, persist to localStorage and reconnect.

**Layout (single-column, mobile-first):**

1. **Header bar (sticky top):**
   - "Draft Companion" title
   - Connection indicator: green dot + "Connected" or red dot + "Disconnected"
   - Compact URL editor (tap to expand)

2. **Current Nomination Section (most prominent):**
   - Player name in large text (24px+)
   - Current bid amount (if available from state)
   - Max bid recommendation from `engineSignals.optimization?.maxBid` — large, bold, colored (green if shouldBid, red if !shouldBid)
   - Value surplus: `engineSignals.optimization?.valueSurplus`
   - Expected market price: `engineSignals.optimization?.expectedMarketPrice`
   - Bid/Pass verdict: green "BID" or red "PASS" based on `shouldBid`
   - Show "Waiting for nomination..." when no current player

3. **Win Probability Section:**
   - `engineSignals.simulation?.winProbability?.winProbability` as a large percentage (note: `simulation.winProbability` is a `SimulationOutcome` object, access its `.winProbability` number field)
   - `engineSignals.simulation?.winProbability?.expectedFinish` as ordinal ("3rd")
   - `engineSignals.simulation?.winProbability?.top3Probability` as top-3 probability
   - If `engineSignals.simulation?.currentDecision` exists, show bid vs pass expected finish comparison from `currentDecision.decisions` array (each entry has `.label` and `.outcome.expectedFinish`)

4. **Budget & Inflation Section:**
   - Remaining budget: `state.remainingBudget` in large text
   - Budget pressure: `engineSignals.budgetCurve?.budgetPressure` as a color-coded bar (green < 0.5, yellow 0.5-0.75, red > 0.75)
   - Inflation factor: `engineSignals.inflation?.inflationFactor` formatted as percentage
   - Remaining slots: show unfilled position counts from `engineSignals.remainingSlots`

5. **Alerts Section:**
   - Render `engineSignals.alerts` as a scrollable list
   - Each alert: severity badge (color-coded), message text
   - Only show alerts with severity >= 0.5

6. **Control Bar (sticky bottom, 60px tall):**
   - Auto-bid toggle: large toggle switch. Sends `sendControl("SET_AUTO_MODE", !currentAutoMode)`. Shows current auto-bid state from `state.autoMode`. Use RED background when auto-bid is ON (it's dangerous).
   - Position filter: compact dropdown with common positions (All, C, 1B, 2B, 3B, SS, OF, SP, RP). Sends `sendControl("SET_POSITION_FILTER", value)`.
   - Pitcher/Hitter split: small slider (0-100). Sends `sendControl("SET_PITCHER_HITTER_SPLIT", value)` on change end.

**Styling:**
- Use existing Tailwind classes from the project.
- `min-h-screen bg-neutral-950 text-neutral-100` — dark background for outdoor visibility.
- All interactive elements: `min-h-[44px] min-w-[44px]` for touch targets.
- Use `font-mono` for numbers/bids.
- Responsive but optimized for 375px+ width (iPhone SE and up).
- No dependency on the design system components (this is a standalone mobile page — inline Tailwind is fine).

**Edge cases:**
- Before connection: show only the URL input and "Connecting..." state.
- Connected but no data yet: show "Waiting for draft data..."
- Extension disconnected (hub relays nothing): show "Extension not connected" warning.
- All number formatting: use `.toFixed(1)` for decimals, `$` prefix for dollar values.
