    **1. Fix sidebarMountObserver scope in content.tsx (lines ~597-608):**
    Change:
    ```typescript
    if (document.documentElement) {
      sidebarMountObserver.observe(document.documentElement, {
        childList: true,
        subtree: true,
      });
    }
    ```
    To:
    ```typescript
    if (document.body) {
      sidebarMountObserver.observe(document.body, {
        childList: true,
        subtree: false,  // sidebar root is a direct body child
      });
    }
    ```
    The sidebar root div is always injected as a direct child of `<body>`. Observing `document.documentElement` with `subtree: true` fires the callback on every single DOM mutation across the entire ESPN page. Narrowing to `document.body` with `subtree: false` limits observation to direct children being added/removed.

    **2. Add shallow equality guard to espnDomAuctionValues setter in draft-state.ts (lines ~282-285):**
    Change:
    ```typescript
    setEspnDomAuctionValues: (values) =>
      set((state) => ({
        espnDomAuctionValues: { ...state.espnDomAuctionValues, ...values },
      })),
    ```
    To:
    ```typescript
    setEspnDomAuctionValues: (values) =>
      set((state) => {
        const hasChanges = Object.entries(values).some(
          ([id, val]) => state.espnDomAuctionValues[Number(id)] !== val
        );
        if (!hasChanges) return state;
        return { espnDomAuctionValues: { ...state.espnDomAuctionValues, ...values } };
      }),
    ```
    This prevents Zustand from notifying subscribers (triggering re-renders in 50+ AuctionPlayerCard instances) when the scraped values haven't actually changed. The scraper runs every 10 seconds — without this guard, every scrape creates a new object reference and re-renders all cards.

    **3. Pre-group allPicks by team in scarcity.ts (around lines ~64-73):**
    Before the position loop, build a Map of teamId -> picks:
    ```typescript
    // Pre-group allPicks by teamId for O(1) team lookup in demand calculation
    const picksByTeam = new Map<string, typeof allPicks>();
    for (const pick of allPicks) {
      if (!picksByTeam.has(pick.teamId)) picksByTeam.set(pick.teamId, []);
      picksByTeam.get(pick.teamId)!.push(pick);
    }
    ```
    Then inside the position loop, change:
    ```typescript
    const posCount = allPicks.filter(
      pick => pick.teamId === teamId &&
        pick.positions.some(p => normalizePosition(p) === position)
    ).length;
    ```
    To:
    ```typescript
    const teamPicks = picksByTeam.get(teamId) ?? [];
    const posCount = teamPicks.filter(
      pick => pick.positions.some(p => normalizePosition(p) === position)
    ).length;
    ```
    This changes the inner loop from O(allPicks) to O(teamPicks) — at late draft with 200 picks and 12 teams, this reduces iterations from 19,200 to ~1,600 for the demand calculation.

    **4. Move draftedPlayerIds/draftedPlayerNames Set construction inside useMemo in AuctionRecommendations.tsx (lines ~34-46):**

    ```typescript
    const draftedPlayerIds = new Set(allPicks.map((p) => p.playerId));

    const availablePlayers = useMemo(() => {
    ```

    ```typescript
    const availablePlayers = useMemo(() => {
      const draftedPlayerIds = new Set(allPicks.map((p) => p.playerId));
      const draftedPlayerNames = new Set(
        allPicks.map((p) => normalizePlayerName(p.playerName)),
      );
      return auctionValues.filter((player) => {
        if (draftedPlayerIds.has(player.playerId)) { return false; }
        return !draftedPlayerNames.has(normalizePlayerName(player.playerName));
      });

    ```
    This ensures the Sets are only constructed when `allPicks` actually changes, not on every render (previously they were constructed outside the memo on every render caused by `espnDomAuctionValues` changes, even though `allPicks` hadn't changed).
